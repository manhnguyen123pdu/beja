PHẦN 1. Tổng quan và cách Upload File

1.1. Upload File là gì?

1.1.1. Khái niệm Upload File

Upload File là quá trình đưa một File từ thiết bị của người dùng lên Server thông qua mạng.

Ví dụ, người dùng sử dụng một ứng dụng Web và chọn một ảnh:

Người dùng
    │
    │ Chọn avatar.jpg
    ▼
Frontend
    │
    │ Gửi File lên Server
    ▼
Backend
    │
    │ Nhận File
    ▼
Server
    │
    └── Lưu File

File có thể là:

  • Hình ảnh: .jpg, .png, .gif, .webp
  • Tài liệu: .pdf, .docx, .xlsx
  • Video: .mp4
  • Âm thanh: .mp3
  • File nén: .zip, .rar

Trong một ứng dụng thực tế, Upload File thường xuất hiện ở các chức năng như:

  • Upload ảnh đại diện người dùng.
  • Upload ảnh sản phẩm.
  • Upload hồ sơ cá nhân.
  • Upload tài liệu.
  • Upload CV.
  • Upload nhiều ảnh cho một sản phẩm.
  • Upload File đính kèm trong bài viết.

1.1.2. Upload File diễn ra như thế nào?

Một quá trình Upload File thông thường gồm các bước:

  1. Bước 1: Người dùng chọn File trên máy tính.
  2. Bước 2: Frontend tạo một HTTP Request chứa File.
  3. Bước 3: Request được gửi đến Backend.
  4. Bước 4: Backend nhận File.
  5. Bước 5: Backend kiểm tra File.
  6. Bước 6: Backend lưu File vào Server hoặc một hệ thống lưu trữ khác.
  7. Bước 7: Backend trả kết quả cho Frontend.

Có thể mô hình hóa như sau:

Client
  │
  │ 1. Chọn File
  ▼
Frontend
  │
  │ 2. POST /api/files/upload
  │    multipart/form-data
  ▼
Spring Boot
  │
  │ 3. MultipartFile
  ▼
Service
  │
  │ 4. Kiểm tra + xử lý
  ▼
Storage
  │
  │ 5. Lưu File
  ▼
Server Disk / Object Storage

1.1.3. Upload File trong ứng dụng Backend

Đối với Backend Java Spring Boot, File Upload thường được xử lý thông qua MultipartFile.

MultipartFile là đối tượng đại diện cho File được gửi từ Client lên Server.

Thông qua MultipartFile, Backend có thể lấy được các thông tin như:

Thông tin Ý nghĩa
File nameTên File
Content typeLoại File
SizeKích thước File
Input streamLuồng đọc dữ liệu File
BytesNội dung File

Ví dụ:

avatar.jpg
    │
    ├── File name: avatar.jpg
    ├── Content type: image/jpeg
    ├── Size: 250 KB
    └── Content: dữ liệu của ảnh

Ở các phần sau, chúng ta sẽ sử dụng MultipartFile để nhận và lưu File trên Server.

1.3. multipart/form-data

1.3.1. multipart/form-data là gì?

multipart/form-data là một kiểu dữ liệu được sử dụng trong HTTP Request để gửi nhiều phần dữ liệu khác nhau trong cùng một Request.

Tên multipart có thể hiểu là:

multi   = nhiều
part    = phần

Tức là một Request có thể được chia thành nhiều phần.

Ví dụ một Request Upload sản phẩm có thể chứa:

Request
│
├── name = "Laptop Dell"
├── price = 15000000
├── description = "Laptop..."
└── image = laptop.jpg

Trong đó:

  • name là dữ liệu text.
  • price là dữ liệu số.
  • description là dữ liệu text.
  • image là File.

Đây là lý do multipart/form-data rất phù hợp cho các API Upload File.

1.3.2. Vì sao không dùng application/json?

Giả sử chúng ta muốn tạo một sản phẩm:

  • Tên sản phẩm
  • Giá
  • Mô tả
  • Ảnh sản phẩm

Nếu chỉ có dữ liệu thông thường:

JSON
{
    "name": "Laptop Dell",
    "price": 15000000,
    "description": "Laptop văn phòng"
}

thì application/json hoàn toàn phù hợp.

Nhưng khi có thêm File:

Laptop Dell
15000000
Laptop văn phòng
laptop.jpg

chúng ta cần một cơ chế cho phép Request chứa cả:

  • Text.
  • Number.
  • File.

Khi đó sử dụng:

HTTP
multipart/form-data

1.3.3. Cấu trúc của Multipart Request

Có thể hình dung một Multipart Request như sau:

HTTP Request
│
├── Part 1
│     └── name = "Laptop Dell"
│
├── Part 2
│     └── price = 15000000
│
├── Part 3
│     └── description = "Laptop văn phòng"
│
└── Part 4
      └── image = laptop.jpg

Mỗi phần được gọi là một Part.

Mỗi Part có thể chứa một loại dữ liệu khác nhau.

1.3.4. Multipart trong Frontend

Ở phía Frontend, khi Upload File, thông thường chúng ta sử dụng FormData.

Ví dụ về mặt ý tưởng:

FormData
│
├── name
├── price
├── description
└── image

Sau đó gửi FormData đến Backend.

Frontend
    │
    │ FormData
    ▼
HTTP Request
    │
    │ multipart/form-data
    ▼
Spring Boot

Phần code Frontend sẽ được trình bày ở bài thực hành sau.

1.4. MultipartFile

1.4.1. MultipartFile là gì?

Trong Spring Boot, MultipartFile là interface được sử dụng để đại diện cho một File được Upload từ Client lên Server.

Có thể hiểu:

Client gửi File
       ↓
multipart/form-data
       ↓
Spring Boot
       ↓
MultipartFile

Backend không trực tiếp nhận File dưới dạng một đường dẫn trên máy Client.

Ví dụ Client có:

C:\Users\Manh\Pictures\avatar.jpg

Server không thể sử dụng trực tiếp đường dẫn này.

Server chỉ nhận được dữ liệu File thông qua HTTP Request.

Sau khi Spring Boot xử lý Request, File được biểu diễn dưới dạng:

Java
MultipartFile

1.4.2. Các thông tin quan trọng của MultipartFile

MultipartFile cung cấp nhiều phương thức để làm việc với File.

Một số phương thức thường sử dụng:

Ví dụ một File:

avatar.jpg

Backend có thể lấy được:

Tên File:
avatar.jpg

Content-Type:
image/jpeg

Size:
250 KB

Phần xử lý tên File sẽ được trình bày chi tiết ở Phần 2.

Khi đó Backend có thể kiểm tra kích thước File trước khi lưu.

Phương thức:

PHẦN 2. Làm việc với File và lưu File trên Server

Sau khi đã hiểu cách Client gửi File lên Backend thông qua multipart/form-data và cách Spring Boot tiếp nhận File bằng MultipartFile, bước tiếp theo là xác định:

  • File sẽ được lưu ở đâu?
  • Server xác định đường dẫn File như thế nào?
  • Làm thế nào để tạo thư mục lưu File?
  • Làm thế nào để ghi File từ MultipartFile xuống ổ đĩa?
  • Nếu hai File có cùng tên thì xử lý như thế nào?
  • Làm thế nào để kiểm tra File trước khi lưu?

Đây là những kiến thức nền tảng trước khi xây dựng API Upload File hoàn chỉnh.

2.1. File được lưu ở đâu?

Khi người dùng Upload một File, Server cần có một nơi để lưu trữ File đó.

Có ba hướng phổ biến:

  • Server Disk
  • Database
  • Object Storage

Trong bài học này, chúng ta tập trung trước vào cách lưu File trên Server Disk.

2.1.1. Server Disk

Server Disk là ổ đĩa của máy Server nơi ứng dụng Backend đang chạy.

Ví dụ Server có cấu trúc:

D:/
└── my-project/
    ├── src/
    ├── target/
    └── uploads/

Khi người dùng Upload:

avatar.jpg

Server có thể lưu thành:

uploads/
└── avatar.jpg

Luồng xử lý:

Client
   │
   │ Upload avatar.jpg
   ▼
Spring Boot
   │
   │ MultipartFile
   ▼
Server Disk
   │
   ▼
uploads/avatar.jpg

Ưu điểm

  • Dễ triển khai.
  • Dễ hiểu.
  • Không cần Database để lưu nội dung File.
  • Phù hợp với các bài tập và ứng dụng nhỏ.

Nhược điểm

  • File phụ thuộc vào ổ đĩa của Server.
  • Khi Server thay đổi hoặc triển khai nhiều Server, việc quản lý File phức tạp hơn.
  • Không phù hợp với hệ thống lớn nếu không có cơ chế lưu trữ riêng.

2.1.2. Lưu File trong Database

Một cách khác là lưu dữ liệu File trực tiếp vào Database.

Ví dụ:

products
files

Thông thường Database sẽ lưu thông tin về File, còn nội dung File được lưu ở một hệ thống Storage.

Ví dụ:

2.2. Path và đường dẫn File

Khi muốn lưu một File trên Server, Backend cần biết File sẽ nằm ở đâu.

Ví dụ:

uploads/avatar.jpg

Đây chính là đường dẫn đến File.

Trong Java, chúng ta thường sử dụng Path để biểu diễn đường dẫn.

2.2.1. Path là gì?

Path là một interface trong Java dùng để biểu diễn đường dẫn đến:

  • File
  • Directory

Ví dụ:

Java
Path path;

Một Path có thể đại diện cho:

uploads

hoặc:

uploads/avatar.jpg

Có thể hình dung:

Path
 │
 ├── Directory
 │
 └── File

2.2.2. Relative Path

Relative Path là đường dẫn tương đối. Nó không chỉ ra toàn bộ vị trí từ gốc của hệ thống.

Ví dụ:

uploads/avatar.jpg

Đây là một Relative Path.

Nó có nghĩa là:

thư mục hiện tại
      │
      └── uploads
             │
             └── avatar.jpg

Relative Path rất thường được sử dụng khi xây dựng ứng dụng.

Ví dụ:

Java
Path path = Paths.get("uploads");

Ở đây uploads là đường dẫn tương đối.

2.2.3. Absolute Path

Absolute Path là đường dẫn đầy đủ xác định chính xác vị trí File trên hệ điều hành.

Ví dụ trên Windows:

C:\Users\Manh\project\uploads\avatar.jpg

Trên Linux có thể là:

/home/manh/project/uploads/avatar.jpg

Có thể hình dung:

Relative Path

uploads/avatar.jpg
        │
        ▼
Không nói rõ vị trí tuyệt đối


Absolute Path

C:\Users\Manh\project\uploads\avatar.jpg
        │
        ▼
Xác định đầy đủ vị trí File

Java

Bởi vì khi chạy trên máy khác, đường dẫn này có thể không tồn tại.

Thay vào đó, chúng ta thường bắt đầu bằng một thư mục tương đối hoặc cấu hình đường dẫn.

Sau khi kết hợp các bước:

Java
package com.example.demo.service;

import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.UUID;

@Service
public class FileService {

    public void upload(MultipartFile file) {

        if (file.isEmpty()) {
            throw new RuntimeException("File không được để trống");
        }

        try {

            Path uploadDir = Paths.get("uploads");

            Files.createDirectories(uploadDir);

            String originalName = file.getOriginalFilename();

            String extension = "";

            if (originalName != null && originalName.contains(".")) {
                extension = originalName.substring(
                        originalName.lastIndexOf(".")
                );
            }

            String fileName = UUID.randomUUID() + extension;

            Path filePath = uploadDir.resolve(fileName);

            file.transferTo(filePath);

        } catch (IOException e) {
            throw new RuntimeException("Không thể lưu File", e);
        }
    }
}

Java
package com.example.demo.service;

import com.example.demo.entity.FileEntity;
import com.example.demo.repository.FileRepository;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.UUID;

@Service
public class FileService {

    private final FileRepository fileRepository;

    private final Path uploadDir = Paths.get("uploads");

    public FileService(FileRepository fileRepository) {
        this.fileRepository = fileRepository;
    }

    public FileEntity uploadFile(MultipartFile file) throws IOException {

        if (file == null || file.isEmpty()) {
            throw new RuntimeException("File không được để trống");
        }

        Files.createDirectories(uploadDir);

        String originalName = file.getOriginalFilename();

        String extension = "";

        if (originalName != null && originalName.contains(".")) {
            extension = originalName.substring(
                    originalName.lastIndexOf(".")
            );
        }

        String fileName = UUID.randomUUID() + extension;

        Path filePath = uploadDir.resolve(fileName);

        file.transferTo(filePath);

        FileEntity fileEntity = new FileEntity();

        fileEntity.setFileName(fileName);
        fileEntity.setOriginalName(originalName);
        fileEntity.setFilePath(filePath.toString());
        fileEntity.setFileType(file.getContentType());
        fileEntity.setFileSize(file.getSize());

        return fileRepository.save(fileEntity);
    }
}

import org.springframework.web.multipart.MultipartFile;

@RestController
@RequestMapping("/api/files")
public class FileController {

    private final FileService fileService;

    public FileController(FileService fileService) {
        this.fileService = fileService;
    }

    @PostMapping("/upload")
    public ResponseEntity<FileEntity> upload(
            @RequestParam("file") MultipartFile file
    ) throws Exception {

        FileEntity result = fileService.uploadFile(file);

        return ResponseEntity.ok(result);
    }
}

6.7.4. Ví dụ Service hoàn chỉnh

Java
@Service
public class FileService {

    private final FileRepository fileRepository;

    private final Path uploadDir =
            Paths.get("uploads")
                    .toAbsolutePath()
                    .normalize();

    public FileService(FileRepository fileRepository) {
        this.fileRepository = fileRepository;
    }

    public FileEntity uploadImage(
            MultipartFile file
    ) throws IOException {

        // 1. Kiểm tra File
        if (file == null || file.isEmpty()) {
            throw new RuntimeException(
                    "File không được để trống"
            );
        }

        // 2. Kiểm tra kích thước
        long maxSize = 5 * 1024 * 1024;

        if (file.getSize() > maxSize) {
            throw new RuntimeException(
                    "File không được vượt quá 5MB"
            );
        }

        // 3. Lấy tên File gốc
        String originalName =
                file.getOriginalFilename();

        if (originalName == null
                || originalName.isBlank()) {

            throw new RuntimeException(
                    "Tên File không hợp lệ"
            );
        }

        // 4. Lấy extension
        String extension = "";

        int index =
                originalName.lastIndexOf(".");

        if (index >= 0) {
            extension = originalName
                    .substring(index)
                    .toLowerCase();
        }

        // 5. Kiểm tra extension
        if (!extension.equals(".jpg")
                && !extension.equals(".jpeg")
                && !extension.equals(".png")) {

            throw new RuntimeException(
                    "Chỉ cho phép JPG, JPEG, PNG"
            );
        }

        // 6. Kiểm tra Content-Type
        String contentType =
                file.getContentType();

        if (!"image/jpeg".equals(contentType)
                && !"image/png".equals(contentType)) {

            throw new RuntimeException(
                    "File không phải ảnh hợp lệ"
            );
        }

        // 7. Tạo thư mục
        Files.createDirectories(uploadDir);

        // 8. Tạo tên File mới
        String fileName =
                UUID.randomUUID() + extension;

        // 9. Tạo Path
        Path filePath =
                uploadDir.resolve(fileName)
                        .normalize();

        // 10. Kiểm tra Path
        if (!filePath.startsWith(uploadDir)) {
            throw new RuntimeException(
                    "Đường dẫn File không hợp lệ"
            );
        }

        try {

            // 11. Lưu File
            file.transferTo(filePath);

            // 12. Tạo Entity
            FileEntity entity =
                    new FileEntity();

            entity.setFileName(fileName);
            entity.setOriginalName(originalName);
            entity.setFilePath(
                    filePath.toString()
            );
            entity.setFileType(contentType);
            entity.setFileSize(file.getSize());

            // 13. Lưu Database
            return fileRepository.save(entity);

        } catch (Exception e) {

            // Nếu Database hoặc quá trình xử lý lỗi
            // thì xóa File vừa tạo

            Files.deleteIfExists(filePath);

            throw e;
        }
    }
}

2.8. Tạo lớp CloudinaryConfig

Bây giờ chúng ta tạo class CloudinaryConfig.java

Ví dụ cấu trúc Package:

src/main/java
└── com.example.demo
    ├── config
    │   └── CloudinaryConfig.java
    │
    ├── controller
    ├── service
    ├── repository
    └── entity

Class:

Java
package com.example.demo.config;

import com.cloudinary.Cloudinary;
import com.cloudinary.utils.ObjectUtils;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class CloudinaryConfig {

    @Value("${cloudinary.cloud-name}")
    private String cloudName;

    @Value("${cloudinary.api-key}")
    private String apiKey;

    @Value("${cloudinary.api-secret}")
    private String apiSecret;

    @Bean
    public Cloudinary cloudinary() {

        return new Cloudinary(
                ObjectUtils.asMap(
                        "cloud_name", cloudName,
                        "api_key", apiKey,
                        "api_secret", apiSecret
                )
        );
    }
}

Đây là class cấu hình quan trọng của bài học.

3.11. Hoàn thiện FileService

Bây giờ chúng ta hoàn thiện Service.

Java
package com.example.demo.service;

import com.cloudinary.Cloudinary;
import com.cloudinary.utils.ObjectUtils;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.util.Map;

@Service
public class FileService {

    private final Cloudinary cloudinary;

    public FileService(Cloudinary cloudinary) {
        this.cloudinary = cloudinary;
    }

    public String upload(MultipartFile file) throws IOException {

        Map result = cloudinary.uploader().upload(
                file.getBytes(),
                ObjectUtils.emptyMap()
        );

        return (String) result.get("secure_url");
    }
}

4.12. Cập nhật FileService

Service cần sử dụng cả:

Cloudinary

Code:

Java
package com.example.demo.service;

import com.cloudinary.Cloudinary;
import com.cloudinary.utils.ObjectUtils;
import com.example.demo.entity.FileEntity;
import com.example.demo.repository.FileRepository;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.time.LocalDateTime;
import java.util.Map;

@Service
public class FileService {

    private final Cloudinary cloudinary;
    private final FileRepository fileRepository;

    public FileService(
            Cloudinary cloudinary,
            FileRepository fileRepository
    ) {
        this.cloudinary = cloudinary;
        this.fileRepository = fileRepository;
    }

    public FileEntity upload(MultipartFile file)
            throws IOException {

        Map result = cloudinary.uploader().upload(
                file.getBytes(),
                ObjectUtils.emptyMap()
        );

        String publicId =
                (String) result.get("public_id");

        String fileUrl =
                (String) result.get("secure_url");

        FileEntity fileEntity = new FileEntity();

        fileEntity.setOriginalName(
                file.getOriginalFilename()
        );

        fileEntity.setPublicId(publicId);

        fileEntity.setFileUrl(fileUrl);

        fileEntity.setFileType(
                file.getContentType()
        );

        fileEntity.setFileSize(
                file.getSize()
        );

        fileEntity.setCreatedAt(
                LocalDateTime.now()
        );

        return fileRepository.save(fileEntity);
    }
}

6.30. Hoàn thiện Service Upload

Một phiên bản tương đối hoàn chỉnh:

Java
@Service
public class FileService {

    private final Cloudinary cloudinary;
    private final FileRepository fileRepository;

    public FileService(
            Cloudinary cloudinary,
            FileRepository fileRepository
    ) {
        this.cloudinary = cloudinary;
        this.fileRepository = fileRepository;
    }

    public FileEntity upload(
            MultipartFile file
    ) throws IOException {

        validateFile(file);

        Map result = cloudinary.uploader().upload(
                file.getBytes(),
                ObjectUtils.asMap(
                        "folder", "uploads"
                )
        );

        String publicId =
                (String) result.get("public_id");

        String fileUrl =
                (String) result.get("secure_url");

        FileEntity fileEntity = new FileEntity();

        fileEntity.setOriginalName(
                file.getOriginalFilename()
        );

        fileEntity.setPublicId(publicId);

        fileEntity.setFileUrl(fileUrl);

        fileEntity.setFileType(
                file.getContentType()
        );

        fileEntity.setFileSize(
                file.getSize()
        );

        fileEntity.setCreatedAt(
                LocalDateTime.now()
        );

        return fileRepository.save(fileEntity);
    }

    private void validateFile(
            MultipartFile file
    ) {

        if (file == null || file.isEmpty()) {
            throw new RuntimeException(
                    "File is empty"
            );
        }

        String contentType =
                file.getContentType();

        if (!"image/jpeg".equals(contentType)
                && !"image/png".equals(contentType)
                && !"image/webp".equals(contentType)) {

            throw new RuntimeException(
                    "Only JPG, PNG and WEBP are allowed"
            );
        }

        long maxSize =
                10 * 1024 * 1024;

        if (file.getSize() > maxSize) {
            throw new RuntimeException(
                    "File size must be less than 10MB"
            );
        }
    }
}

Đây là phiên bản phù hợp để hiểu đầy đủ quy trình:

Validate
   ↓
Upload Cloudinary
   ↓
Get public_id
   ↓
Get secure_url
   ↓
Create Entity
   ↓
Save Database

6.40. Kết luận

Cloudinary giúp ứng dụng Spring Boot không phải tự xây dựng toàn bộ hệ thống lưu trữ File.

Có thể chia trách nhiệm thành:

Cloudinary
    ↓
Lưu trữ File thật
    ↓
Quản lý File
    ↓
Phân phối File

Trong khi:

Database
    ↓
Lưu Metadata
    ↓
Lưu quan hệ với User/Product/Post
    ↓
Lưu publicId
    ↓
Lưu fileUrl

Và Spring Boot đóng vai trò trung gian:

Client
   ↓
Spring Boot
   ├── Validate
   ├── Upload
   ├── Lưu Database
   ├── Lấy File
   └── Xóa File
   ↓
Cloudinary + Database
Công thức quan trọng nhất cần nhớ
  • File thật → Cloudinary
  • Thông tin File → Database
  • Truy cập File → secure_url / fileUrl
  • Xóa File → public_id
  • Bảo mật → Không để lộ API_SECRET

Đây chính là mô hình cơ bản và phổ biến khi xây dựng chức năng Upload File trong Spring Boot sử dụng Cloudinary.
