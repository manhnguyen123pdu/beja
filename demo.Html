PHẦN 1. Tổng quan và cách Upload File

Trong các ứng dụng web thực tế, người dùng không chỉ gửi dữ liệu dạng văn bản như họ tên, email, mật khẩu... mà còn thường xuyên cần gửi file lên Server.

Ví dụ:

  • Đăng ảnh đại diện.
  • Đăng ảnh sản phẩm.
  • Upload CV.
  • Upload tài liệu PDF.
  • Upload nhiều hình ảnh của một bài đăng.
  • Upload file Excel, Word...

Spring Boot cung cấp cơ chế hỗ trợ Upload File thông qua MultipartFile. Tuy nhiên, trước khi sử dụng MultipartFile, cần hiểu cách HTTP gửi File từ Client lên Server và tại sao Upload File không giống với việc gửi JSON.

1.1. Upload File là gì?

1.1.1. Khái niệm

Upload File là quá trình Client gửi một file lên Server để Server tiếp nhận và xử lý file đó.

Ví dụ người dùng chọn một ảnh:

avatar.jpg

Sau đó nhấn nút:

[ Upload ]

Client sẽ gửi file avatar.jpg đến Server.

Server nhận file và có thể:

  • Lưu file vào ổ đĩa.
  • Lưu file vào Object Storage.
  • Kiểm tra định dạng.
  • Kiểm tra kích thước.
  • Đổi tên file.
  • Lưu đường dẫn file vào Database.
  • Trả về URL để Client hiển thị file.

1.1.2. Ví dụ thực tế

Giả sử xây dựng chức năng:

Upload Avatar

Người dùng chọn:

cat.jpg

Client gửi:

cat.jpg
      ↓
   Server
      ↓
uploads/a8f52c91.jpg

Database có thể lưu:

/users
--------------------------------
id | username | avatar
--------------------------------
1  | admin    | /uploads/a8f52c91.jpg

Như vậy:

File thật nằm ở nơi lưu trữ, còn Database thường chỉ lưu đường dẫn hoặc URL của File.

Đây là nguyên tắc rất quan trọng khi thiết kế chức năng Upload File.

1.2. Upload File khác gửi JSON như thế nào?

Trước khi học Upload File, chúng ta thường làm việc với API nhận dữ liệu JSON.

Ví dụ Client gửi thông tin User:

JSON
{
    "username": "admin",
    "email": "admin@gmail.com"
}

Request thường có:

HTTP
Content-Type: application/json

Server nhận dữ liệu thông qua DTO:

Java
@PostMapping("/users")
public User createUser(@RequestBody UserRequest request) {
    ...
}

Ở đây toàn bộ dữ liệu nằm trong JSON.

1.2.1. JSON phù hợp với dữ liệu dạng text

Ví dụ:

JSON
{
    "name": "Nguyen Van A",
    "age": 25,
    "email": "a@gmail.com"
}

Các dữ liệu như:

  • String
  • Number
  • Boolean
  • Object
  • Array

đều có thể biểu diễn bằng JSON.

Nhưng File như:

avatar.jpg
document.pdf
product.png
cv.docx

không phải dữ liệu JSON thông thường.

Do đó không thể đơn giản làm:

JSON
{
    "avatar": "???"
}

để gửi trực tiếp một file ảnh lên Server.

1.2.2. Có thể gửi File dưới dạng Base64 không?

Về mặt kỹ thuật, có thể chuyển File thành chuỗi Base64 rồi đưa vào JSON.

Ví dụ:

JSON
{
    "fileName": "avatar.jpg",
    "file": "/9j/4AAQSkZJRgABAQAAAQ..."
}

Tuy nhiên, cách này thường không phải lựa chọn phù hợp cho Upload File thông thường vì:

  • Dữ liệu lớn hơn.
  • Request JSON trở nên rất dài.
  • Tốn thêm tài nguyên để mã hóa/giải mã.
  • Không thuận tiện khi upload file lớn.

Thay vào đó, HTTP có một cơ chế phù hợp hơn:

multipart/form-data

1.3. multipart/form-data

1.3.1. Content-Type là gì?

Khi Client gửi HTTP Request, nó cần cho Server biết dữ liệu đang được gửi có dạng gì.

Thông tin này được khai báo thông qua:

HTTP
Content-Type

Ví dụ:

Gửi JSON

HTTP
Content-Type: application/json

Gửi Form thông thường

HTTP
Content-Type: application/x-www-form-urlencoded

Upload File

HTTP
Content-Type: multipart/form-data

1.3.2. multipart/form-data là gì?

multipart/form-data là một kiểu dữ liệu HTTP được thiết kế để gửi nhiều phần dữ liệu khác nhau trong cùng một Request.

Ví dụ một Request có thể chứa:

username = admin
email = admin@gmail.com
avatar = cat.jpg

Trong đó:

username
email

là dữ liệu text.

Còn:

avatar

là một File.

Vì vậy Request có thể chứa nhiều "part":

HTTP Request
│
├── Part 1: username
│
├── Part 2: email
│
└── Part 3: avatar.jpg

Đó chính là ý nghĩa của từ:

multipart

Có thể hiểu đơn giản:

Một Request được chia thành nhiều phần (parts), mỗi phần có thể chứa một loại dữ liệu khác nhau.

1.3.3. Ví dụ Upload File bằng Form

Trên Client, người dùng có thể có một Form:

Username: [ admin              ]

Email:    [ admin@gmail.com    ]

Avatar:   [ Choose File...     ]

          [ Upload ]

Khi nhấn Upload, Client gửi:

multipart/form-data

với các part:

username → "admin"

email → "admin@gmail.com"

avatar → cat.jpg

Server có thể lấy từng phần riêng biệt.

1.3.4. So sánh JSON và Multipart

Đặc điểm JSON multipart/form-data
Gửi textCóCó
Gửi sốCóCó
Gửi objectCóCó thể xử lý
Gửi FileKhông phù hợp trực tiếpCó
Upload ảnhKhông phù hợpPhù hợp
Upload PDFKhông phù hợpPhù hợp
Content-Typeapplication/jsonmultipart/form-data

Có thể ghi nhớ:

Dữ liệu thông thường
        ↓
      JSON

File
        ↓
multipart/form-data

1.4. MultipartFile

Sau khi Client gửi File bằng multipart/form-data, vấn đề tiếp theo là:

Spring Boot nhận File bằng kiểu dữ liệu nào?

Câu trả lời là:

Java
MultipartFile

MultipartFile là interface của Spring dùng để đại diện cho một File được upload từ HTTP Request.

Package:

Java
org.springframework.web.multipart.MultipartFile

1.4.1. Tư duy quan trọng

Không nên hiểu:

MultipartFile = File được lưu trên ổ đĩa

mà nên hiểu:

MultipartFile = File mà Server vừa nhận được từ Client

Nó đại diện cho dữ liệu File trong quá trình Request được xử lý.

Sau khi nhận được MultipartFile, Server mới quyết định:

MultipartFile
      ↓
Validate
      ↓
Đổi tên
      ↓
Lưu File

1.4.2. Nhận File trong Controller

Ví dụ đơn giản:

Java
@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    return "Upload thành công";
}

Ở đây:

Java
MultipartFile file

là File mà Client gửi lên.

Còn:

Java
@RequestParam("file")

cho Spring biết rằng cần lấy phần có tên:

file

trong multipart/form-data.

1.4.3. Tên file lấy từ đâu?

Ví dụ Client gửi:

Key: file
Type: File
Value: cat.jpg

thì Controller:

Java
@RequestParam("file")

sẽ lấy đúng part đó.

Nếu Client gửi:

Key: avatar

thì Controller phải tương ứng:

Java
@RequestParam("avatar")
MultipartFile file

Tên giữa Client và Server phải khớp nhau.

1.4.4. Upload nhiều File

MultipartFile đại diện cho một File.

Nếu muốn nhận nhiều File, có thể sử dụng:

Java
MultipartFile[] files

hoặc:

Java
List<MultipartFile> files

Ví dụ:

Java
@PostMapping("/upload-multiple")
public String upload(
        @RequestParam("files") List<MultipartFile> files) {

    return "Upload thành công";
}

Khi đó:

files
├── image1.jpg
├── image2.jpg
└── image3.png

1.5. Các thông tin có thể lấy từ MultipartFile

Sau khi Server nhận được:

Java
MultipartFile file

chúng ta có thể lấy nhiều thông tin từ File.

Các thông tin quan trọng gồm:

  1. Tên File.
  2. Kích thước File.
  3. Content-Type.
  4. Nội dung File.

1.5.1. Tên File

Để lấy tên File mà Client gửi lên:

Java
file.getOriginalFilename()

Ví dụ người dùng upload:

avatar.jpg

thì:

Java
String fileName = file.getOriginalFilename();

có thể nhận được:

avatar.jpg

Lưu ý: Đây là tên File do Client gửi lên. Không nên mặc định dùng tên này làm tên File cuối cùng trên Server.

Ví dụ:

avatar.jpg

có thể được đổi thành:

a82f91c3-5c7a-4b6e.jpg

Việc đổi tên sẽ được học kỹ hơn ở phần xử lý lưu File.

1.5.2. Kích thước

Để lấy kích thước File:

Java
file.getSize()

Giá trị trả về có đơn vị:

byte

Ví dụ:

Java
long size = file.getSize();

Nếu File có kích thước:

2 MB

thì getSize() sẽ trả về số byte tương ứng.

Thông tin này thường được sử dụng để:

  • Kiểm tra File quá lớn.
  • Giới hạn kích thước upload.
  • Hiển thị kích thước File.
  • Kiểm soát tài nguyên Server.

1.5.3. Content-Type

Để lấy loại dữ liệu của File:

Java
file.getContentType()

Ví dụ:

image/jpeg

đối với ảnh JPG/JPEG.

Một số Content-Type thường gặp:

File Content-Type
JPGimage/jpeg
PNGimage/png
GIFimage/gif
WebPimage/webp
PDFapplication/pdf
JSONapplication/json
ZIPapplication/zip

Ví dụ:

Java
String contentType = file.getContentType();

Có thể dùng thông tin này để kiểm tra:

File có phải ảnh hay không?

Ví dụ:

Java
if (!"image/jpeg".equals(file.getContentType())) {
    // từ chối
}

Tuy nhiên, chỉ kiểm tra Content-Type cũng chưa đủ an toàn. Phần Validate File sẽ được học ở Phần 3.

1.5.4. Nội dung File

MultipartFile cũng cho phép lấy dữ liệu bên trong File.

Có thể lấy dưới dạng InputStream:

Java
InputStream inputStream = file.getInputStream();

InputStream là cơ chế của Java dùng để đọc dữ liệu từ một nguồn dữ liệu theo dạng luồng.

Trong trường hợp này:

MultipartFile
      ↓
getInputStream()
      ↓
InputStream
      ↓
Đọc nội dung File

Hoặc có thể lấy toàn bộ dữ liệu dưới dạng mảng byte:

Java
byte[] bytes = file.getBytes();

Ví dụ:

Java
byte[] data = file.getBytes();

Khi đó:

data
 ↓
toàn bộ dữ liệu của File

Tuy nhiên, với File lớn, không nên tùy tiện đọc toàn bộ File vào byte[] vì có thể tốn nhiều bộ nhớ. Khi xử lý File thực tế, InputStream thường phù hợp hơn cho các thao tác đọc theo luồng.

1.5.5. Kiểm tra File có rỗng hay không

MultipartFile còn có phương thức:

Java
file.isEmpty()

Phương thức này dùng để kiểm tra File có dữ liệu hay không.

Ví dụ:

Java
if (file.isEmpty()) {
    return "File không được để trống";
}

Đây thường là một trong những bước kiểm tra đầu tiên khi nhận File.

1.5.6. Tổng hợp các phương thức quan trọng

Phương thức Ý nghĩa
getOriginalFilename()Lấy tên File gốc
getSize()Lấy kích thước File
getContentType()Lấy Content-Type
getInputStream()Lấy luồng đọc File
getBytes()Lấy toàn bộ dữ liệu File
isEmpty()Kiểm tra File rỗng

Có thể ghi nhớ:

MultipartFile
│
├── Tên       → getOriginalFilename()
├── Kích thước → getSize()
├── Loại       → getContentType()
├── Nội dung   → getInputStream()
├── Byte       → getBytes()
└── Rỗng       → isEmpty()

1.6. Luồng Upload File

Sau khi đã hiểu:

  • Upload File là gì.
  • multipart/form-data là gì.
  • MultipartFile là gì.
  • Server có thể lấy thông tin gì từ File.

Bây giờ có thể nhìn toàn bộ quá trình.

1.6.1. Luồng cơ bản

Client
   ↓
multipart/form-data
   ↓
Controller
   ↓
MultipartFile
   ↓
Storage

Trong đó mỗi bước có ý nghĩa:

Bước 1: Client

Người dùng chọn File.

Ví dụ:

cat.jpg

Bước 2: multipart/form-data

Client đóng gói File vào HTTP Request dưới dạng:

multipart/form-data

Request có thể chứa:

file = cat.jpg

hoặc:

username = admin
email = admin@gmail.com
file = cat.jpg

Bước 3: Controller

Request đi đến API của Spring Boot.

Ví dụ:

POST /api/files/upload

Controller nhận File:

Java
MultipartFile file

Bước 4: MultipartFile

Spring tạo đối tượng:

Java
MultipartFile

đại diện cho File vừa nhận.

Server có thể kiểm tra:

Tên File
Kích thước
Content-Type
Nội dung

Bước 5: Storage

Sau khi kiểm tra, Server lưu File vào nơi lưu trữ.

Ví dụ:

uploads/
└── a82f91c3.jpg

Ở các phần tiếp theo, chúng ta sẽ học cách xây dựng Storage để thực hiện việc này.
