JWT AUTHENTICATION FILTER

1. JWT Authentication Filter

Trong quá trình xây dựng hệ thống xác thực bằng JWT, việc tạo JWT sau khi đăng nhập thành công mới chỉ là bước đầu tiên.

Sau khi người dùng nhận được JWT, ở những request tiếp theo, client phải gửi JWT lên server để chứng minh rằng mình đã đăng nhập.

Ví dụ:

HTTP Request
GET /api/users/profile HTTP/1.1
Host: localhost:8080
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Lúc này, server cần thực hiện một loạt công việc:

Client
   │
   │ Request + JWT
   ▼
Spring Security
   │
   ▼
JWT Authentication Filter
   │
   ├── Đọc JWT từ Request
   │
   ├── Kiểm tra JWT
   │
   ├── Lấy thông tin User
   │
   ├── Tạo Authentication
   │
   └── Đưa Authentication vào SecurityContext
   │
   ▼
Controller

Đây chính là nhiệm vụ trung tâm của JWT Authentication Filter.

JWT Filter có thể hiểu đơn giản là một bộ lọc nằm trong quá trình xử lý request của Spring Security, có nhiệm vụ kiểm tra xem request có chứa JWT hợp lệ hay không và nếu hợp lệ thì thiết lập thông tin xác thực cho request đó.

Trong chương này, chúng ta sẽ lần lượt tìm hiểu cách xây dựng cơ chế này.

1.1. JWT Filter là gì?

Trước hết, cần hiểu rõ JWT Filter đứng ở đâu trong toàn bộ quá trình authentication.

Header
Authorization: Bearer <JWT>

Ở phía server, cần có một thành phần nhận request và kiểm tra JWT trước khi request được xử lý tiếp.

Thành phần đó chính là:

JwtAuthenticationFilter

Có thể hình dung:

HTTP Request
     │
     ▼
JwtAuthenticationFilter
     │

     │

Nói cách khác:

JWT Authentication Filter là thành phần của Spring Security dùng để đọc và xử lý JWT được gửi từ client trong mỗi HTTP request cần xác thực.

Trong phần triển khai chi tiết, chúng ta sẽ tìm hiểu:

  • Filter lấy JWT từ đâu.
  • Cách đọc HTTP Header.
  • Cách xử lý Authorization: Bearer <token>.
  • Cách kiểm tra JWT.
  • Cách lấy username hoặc subject từ JWT.
  • Cách tạo đối tượng Authentication.
  • Cách đưa authentication vào SecurityContext.

1.2. Vì sao cần JWT Filter?

Một câu hỏi quan trọng là:

Nếu đã có JWT rồi thì tại sao phải tạo thêm JwtAuthenticationFilter?

Lý do là JWT tự nó không làm cho Spring Security biết người dùng đã được xác thực.

Ví dụ client gửi:

Request
GET /api/users
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Việc request có JWT không có nghĩa là Spring Security tự động biết JWT đó là gì.

Spring Security cần có một cơ chế để:

Đọc JWT
   ↓
Kiểm tra JWT
   ↓
Xác định User
   ↓
Tạo Authentication
   ↓
SecurityContext

Nếu không có Filter xử lý JWT, request có thể chứa token nhưng Spring Security vẫn không có thông tin authentication cần thiết để xác định:

  • Request này đến từ ai?
  • User đã đăng nhập chưa?
  • Authentication hiện tại là gì?
Vai trò của JWT Filter

Có thể tóm tắt nhiệm vụ của JWT Filter như sau:

BướcNhiệm vụ
1Nhận HTTP Request
2Kiểm tra request có JWT hay không
3Lấy JWT từ Authorization Header
4Kiểm tra JWT
5Lấy thông tin người dùng từ JWT
6Tạo Authentication
7Đưa Authentication vào SecurityContext
8Cho request tiếp tục đi qua Security Filter Chain

Toàn bộ quá trình này sẽ được triển khai cụ thể ở các phần sau.

1.3. OncePerRequestFilter

Để xây dựng JWT Filter trong Spring Boot/Spring Security, chúng ta cần một cơ chế Filter phù hợp.

Spring cung cấp lớp:

OncePerRequestFilter
OncePerRequestFilter

Đây là một lớp abstract thuộc Spring Web, được thiết kế để đảm bảo logic Filter được thực hiện một lần cho mỗi request dispatch.

Thay vì tự xây dựng một Servlet Filter hoàn chỉnh, chúng ta có thể kế thừa:

OncePerRequestFilter
OncePerRequestFilter

Ví dụ về cấu trúc:

JwtAuthenticationFilter.java
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain) throws ServletException, IOException {

        // Xử lý JWT

        filterChain.doFilter(request, response);
    }
}

Trong phần này, người học sẽ làm quen với:

  • OncePerRequestFilter là gì.
  • Vì sao JWT Filter thường kế thừa lớp này.
  • doFilterInternal() có vai trò gì.
  • HttpServletRequest dùng để làm gì.
  • HttpServletResponse dùng để làm gì.
  • FilterChain dùng để làm gì.
  • Vì sao cần gọi: filterChain.doFilter(request, response);

Đây là nền tảng để chúng ta xây dựng JwtAuthenticationFilter ở phần tiếp theo.

Các bước xử lý của JWT Filter
  • Bước 1: Đọc Authorization Header
    Authorization: Bearer <token>
  • Bước 2: Kiểm tra định dạng Bearer Token
    Filter cần xác định request có thực sự chứa: Bearer <JWT> hay không.
  • Bước 3: Extract JWT
    Tách token ra khỏi chuỗi: Bearer eyJhbGciOiJIUzI1NiJ9... để thu được: eyJhbGciOiJIUzI1NiJ9...
  • Bước 4: Validate JWT
    JWT cần được kiểm tra trước khi sử dụng.
    Ví dụ:
    • JWT có hợp lệ không?
    • JWT có bị sửa đổi không?
    • JWT có hết hạn không?
    • Signature có chính xác không?
  • Bước 5: Lấy thông tin User
    Sau khi JWT hợp lệ, Filter có thể lấy thông tin định danh, chẳng hạn: username hoặc: subject từ JWT.
  • Bước 6: Tạo Authentication
    Sau khi xác định được người dùng, Filter tạo đối tượng: Authentication để Spring Security sử dụng thông tin này trong quá trình xử lý request.
  • Bước 7: Đưa Authentication vào SecurityContext
    Cuối cùng: Authentication → SecurityContext.
    Từ đó, Spring Security có thể biết request hiện tại đang được thực hiện bởi user nào.

2. ĐỌC JWT TỪ HTTP REQUEST

Ở chương trước, chúng ta đã biết JwtAuthenticationFilter có nhiệm vụ xử lý JWT trước khi request đi vào Controller.

Tuy nhiên, muốn xử lý được JWT thì trước tiên Filter phải lấy được JWT từ HTTP Request.

Đây là bước đầu tiên trong quá trình xác thực:

HTTP Request
     │
     ▼
Authorization Header
     │
     ▼
Bearer <JWT>
     │
     ▼
JWT
     │
     ▼
Validate JWT
     │
     ▼
Authentication

Ví dụ client gửi request:

HTTP Request
GET /api/users/profile HTTP/1.1
Host: localhost:8080
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhZG1pbiJ9...

Trong request trên, JWT nằm trong HTTP Header có tên:

Header
Authorization

và có dạng:

Value
Bearer <token>

Do đó, nhiệm vụ đầu tiên của JwtAuthenticationFilter là đọc Header này.

2.1. Authorization Header

2.1.1. HTTP Header là gì?

HTTP Request được gửi từ client lên server thường bao gồm nhiều thành phần:

HTTP Request
│
├── Method
│
├── URL
│
├── Headers
│
└── Body

Ví dụ:

Request
POST /api/auth/login HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{
    "username": "admin",
    "password": "123456"
}

Trong request trên:

  • POST là HTTP Method.
  • /api/auth/login là URL/endpoint.
  • Content-Type: application/json là HTTP Header.
  • Phần {"username": "admin","password": "123456"} là HTTP Body.

2.1.2. Authorization Header là gì?

Authorization là một HTTP Header được sử dụng để truyền thông tin xác thực từ client đến server.

Ví dụ:

Header
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Có thể hiểu đơn giản:

Authorization
      │
      ▼
Thông tin xác thực
      │
      ▼
Bearer JWT

Trong hệ thống JWT, chúng ta thường sử dụng Header này để gửi Access Token.

2.1.3. JWT được đặt ở đâu?

JWT không phải là toàn bộ giá trị của Authorization.

Ví dụ:

Header
Authorization: Bearer abc123xyz

Trong đó:

Authorization
      │
      └── Bearer abc123xyz
                │
                ├── Bearer
                │
                └── abc123xyz
                      │
                      └── JWT

Do đó:

  • Header name: Authorization
  • Header value: Bearer <token>

Hai thành phần này cần được phân biệt rõ.

2.2. Cấu trúc Authorization: Bearer <token>

Đây là cấu trúc rất quan trọng khi làm JWT Authentication.

Một request thường có dạng:

Header
Authorization: Bearer <token>

Ví dụ:

Header
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhZG1pbiJ9...

Cấu trúc:

Authorization: Bearer <token>
              │       │
              │       └── JWT
              │
              └── Authentication Scheme

2.2.1. Authorization

Đây là tên của HTTP Header.

Code
Authorization

Spring có thể đọc giá trị Header này từ:

Code
HttpServletRequest

2.2.2. Bearer

Bearer là authentication scheme cho biết token được gửi theo dạng Bearer Token.

Ví dụ:

Header
Bearer abc123

Trong đó:

  • Bearer không phải là JWT.
  • Nó chỉ là tiền tố cho biết phần phía sau là access token.

2.2.3. <token>

Phần <token> mới chính là JWT mà server cần xử lý.

Ví dụ:

Header
Bearer eyJhbGciOiJIUzI1NiJ9...

thì:

  • Bearer là tiền tố.
  • eyJhbGciOiJIUzI1NiJ9... là JWT.

Vì vậy Filter cần thực hiện thao tác:

Authorization Header
        │
        ▼
Bearer <JWT>
        │
        ▼
Bỏ "Bearer "
        │
        ▼
JWT

2.2.4. Tại sao phải có Bearer?

Nếu client chỉ gửi:

Header
Authorization: eyJhbGciOiJIUzI1NiJ9...

thì server khó xác định cách thức xác thực mà client đang sử dụng.

Khi sử dụng:

Header
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

request thể hiện rõ:

Authorization
      ↓
Bearer Authentication
      ↓
JWT Token

Đây là cách gửi Bearer Token tiêu chuẩn và phổ biến trong các REST API sử dụng JWT.

2.3. Kiểm tra Header có tồn tại hay không

Bây giờ chúng ta bắt đầu viết code.

Trong JwtAuthenticationFilter, chúng ta có:

JwtAuthenticationFilter.java
HttpServletRequest request

Đối tượng này đại diện cho HTTP Request hiện tại.

Spring cung cấp phương thức:

Code
request.getHeader()

để lấy giá trị của HTTP Header.

Ví dụ:

JwtAuthenticationFilter.java
String authHeader = request.getHeader("Authorization");

Sau câu lệnh này, biến authHeader sẽ chứa giá trị của Header Authorization.

2.3.1. Ví dụ request có JWT

Client gửi:

Request
GET /api/users HTTP/1.1
Authorization: Bearer abc123

Code:

Code
String authHeader = request.getHeader("Authorization");

Kết quả:

authHeader ↓ "Bearer abc123"

2.3.2. Trường hợp Header không tồn tại

Nếu client không gửi Authorization thì:

Code
request.getHeader("Authorization")

sẽ trả về:

null

Ví dụ request:

Request
GET /api/users HTTP/1.1
Host: localhost:8080

Không có Authorization nên:

String authHeader = request.getHeader("Authorization"); kết quả: authHeader = null

2.3.3. Vì sao phải kiểm tra null?

Nếu chúng ta không kiểm tra authHeader mà thực hiện ngay:

Code
authHeader.startsWith("Bearer ")

thì khi Header không tồn tại:

authHeader = null

sẽ xảy ra:

NullPointerException

Do đó phải kiểm tra trước.

Ví dụ:

Code
String authHeader = request.getHeader("Authorization");

if (authHeader == null) {
    filterChain.doFilter(request, response);
    return;
}

Ý nghĩa:

Có Authorization Header?
        │
   ┌────┴────┐
   │         │
  Có        Không
   │         │
   ▼         ▼
Xử lý      Bỏ qua
JWT        JWT

2.3.4. Tại sao không có JWT thì cho request đi tiếp?

Không phải request nào cũng yêu cầu JWT.

Ví dụ:

API Login
POST /api/auth/login

Client chưa có JWT thì làm sao gửi JWT?

Vì vậy request login thường phải được phép đi qua mà không cần JWT.

Tương tự có thể có:

API Public
GET /api/public

là API public.

Do đó JWT Filter thường không tự động chặn request chỉ vì không có JWT.

Nó có thể thực hiện:

Code
if (authHeader == null) {
    filterChain.doFilter(request, response);
    return;
}

Sau đó Spring Security sẽ tiếp tục quyết định request đó có được phép truy cập hay không.

Điểm này rất quan trọng:

JWT Filter có nhiệm vụ cố gắng xác thực JWT nếu request có JWT; việc request có bắt buộc phải đăng nhập hay không còn phụ thuộc vào cấu hình Spring Security.

2.4. Kiểm tra tiền tố Bearer

Sau khi xác định Header tồn tại, chúng ta cần kiểm tra tiếp: Header có đúng định dạng Bearer Token hay không?

Ví dụ hợp lệ:

Header
Bearer abc123

Ví dụ không đúng:

Header
Basic abc123

hoặc:

Header
Token abc123

hoặc:

Header
abc123

Do đó cần kiểm tra tiền tố Bearer.

2.4.1. Sử dụng startsWith()

Java String cung cấp phương thức startsWith() để kiểm tra một chuỗi có bắt đầu bằng chuỗi khác hay không.

Ví dụ:

Code
String value = "Bearer abc123";

value.startsWith("Bearer ");
kết quả: true

Trong khi:

Code
String value = "Basic abc123";

value.startsWith("Bearer ");
kết quả: false

2.4.2. Áp dụng vào JWT Filter

Code:

JwtAuthenticationFilter.java
String authHeader = request.getHeader("Authorization");

if (authHeader == null || !authHeader.startsWith("Bearer ")) {
    filterChain.doFilter(request, response);
    return;
}

Đây là một đoạn code rất quan trọng.

Có thể đọc theo ngôn ngữ tự nhiên:

  • Nếu Authorization Header không tồn tại
  • HOẶC
  • Authorization Header không bắt đầu bằng "Bearer "
  • THÌ
  • cho request đi tiếp
  • kết thúc Filter

2.4.3. Phân tích điều kiện

Giải thích:

  • authHeader == null – kiểm tra Header có tồn tại không?
  • !authHeader.startsWith("Bearer ") – kiểm tra Header có KHÔNG bắt đầu bằng "Bearer " không?

Kết hợp:

if (authHeader == null || !authHeader.startsWith("Bearer ")) {

có nghĩa:

                   Authorization
                         │
               ┌─────────┴─────────┐
               │                   │
          Header null?        Bắt đầu Bearer?
               │                   │
              Có                  Có
               │                   │
               └────────┬──────────┘
                        │
                       Xử lý

Nếu không phải Bearer Token thì Filter không xử lý JWT.

2.5. Tách JWT khỏi Header

Đây là bước cuối cùng của phần đọc JWT.

2.5.1. Sử dụng substring()

Java cung cấp substring() để lấy một phần của String.

Ví dụ:

Ta có thể viết:

Code

Kết quả:

abc123

Tại sao là 7?

Bởi vì:

  • Bearer có 6 ký tự: B e a r e r (1 2 3 4 5 6)
  • sau đó là một dấu cách: Bearer_ (dấu cách là vị trí thứ 7)

Tổng cộng: 6 + 1 = 7

Vì vậy authHeader.substring(7); sẽ lấy toàn bộ nội dung bắt đầu từ ký tự thứ 8 (chỉ số 7).

JwtService.java
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;
import java.util.Date;
import java.util.function.Function;

@Service
public class JwtService {

    @Value("${jwt.secret-key}")
    private String secretKey;

    @Value("${jwt.expiration}")
    private long expiration;

    // 1. TẠO JWT TOKEN
    public String generateToken(UserDetails userDetails) {
        return Jwts.builder()
                .subject(userDetails.getUsername())
                .claim(
                        "role",
                        userDetails.getAuthorities()
                                .stream()
                                .findFirst()
                                .map(GrantedAuthority::getAuthority)
                                .orElse("")
                )
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis()+ expiration))
                .signWith(getKey())
                .compact();
    }
    // 2. LẤY USERNAME TỪ TOKEN
    public String extractUsername(String token) {
        return extractClaim(token,Claims::getSubject);
    }
    // 3. LẤY CLAIM
    public  T extractClaim(String token,Function claimsResolver) {
        Claims claims = Jwts.parser()
                .verifyWith(getKey())
                .build()
                .parseSignedClaims(token)
                .getPayload();
        return claimsResolver.apply(claims);
    }
    // 4. KIỂM TRA TOKEN HỢP LỆ
    public boolean isTokenValid(String token,UserDetails userDetails ) {
        String username = extractUsername(token);
        return username.equals(userDetails.getUsername())&& !isTokenExpired(token);
    }
    // 5. KIỂM TRA TOKEN HẾT HẠN
    private boolean isTokenExpired(String token) {
        return extractExpiration(token).before(new Date());
    }
    // 6. LẤY THỜI GIAN HẾT HẠN
    private Date extractExpiration(String token) {
        return extractClaim(token,Claims::getExpiration
        );
    }
    // 7. TẠO SECRET KEY
    private SecretKey getKey() {
        return Keys.hmacShaKeyFor(Decoders.BASE64.decode(secretKey));
    }
}

        // =========================================

        if (authHeader == null
                || !authHeader.startsWith("Bearer ")) {

            filterChain.doFilter(request, response);
            return;
        }

        // =========================================
        // 3. Tách JWT
        // =========================================

        String jwt =
                authHeader.substring(7);

        try {

            // =========================================
            // 4. Lấy username từ JWT
            // =========================================

            String username =
                    jwtService.extractUsername(jwt);

            // =========================================
            // 5. Kiểm tra SecurityContext
            // =========================================

            if (username != null
                    && SecurityContextHolder
                        .getContext()
                        .getAuthentication() == null) {

                // =====================================
                // 6. Load UserDetails
                // =====================================

                UserDetails userDetails =
                        userDetailsService
                                .loadUserByUsername(username);

                // =====================================
                // 7. Validate JWT
                // =====================================

                if (jwtService.isTokenValid(
                        jwt,
                        userDetails)) {

                    // =================================
                    // 8. Tạo Authentication
                    // =================================

                    UsernamePasswordAuthenticationToken authentication =
                            new UsernamePasswordAuthenticationToken(
                                    userDetails,
                                    null,
                                    userDetails.getAuthorities()
                            );

                    // =================================
                    // 9. Đưa Authentication vào
                    //    SecurityContext
                    // =================================

                    SecurityContextHolder
                            .getContext()
                            .setAuthentication(authentication);
                }
            }

        } catch (Exception e) {

            // JWT không hợp lệ
            response.setStatus(
                    HttpServletResponse.SC_UNAUTHORIZED
            );

            return;
        }

        // =========================================
        // 10. Cho request tiếp tục
        // =========================================

        filterChain.doFilter(request, response);
    }
}

import com.example.security.security.JwtAuthenticationFilter;
import lombok.RequiredArgsConstructor;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;

import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;

import org.springframework.security.config.http.SessionCreationPolicy;

import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;


@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;
    // SECURITY FILTER CHAIN
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                // 1. TẮT CSRF
                .csrf(csrf -> csrf.disable())
                // 2. SESSION STATELESS
                .sessionManagement(session ->
                        session.sessionCreationPolicy(
                                SessionCreationPolicy.STATELESS
                        )
                )
                // 3. AUTHORIZATION
                .authorizeHttpRequests(auth -> auth

                        // Login / Register Không cần JWT
                        .requestMatchers("/api/auth/**")

                        .permitAll()
                        // API dành cho USER
                        .requestMatchers("/api/demo/user")
                        .hasRole("USER")

                        // API dành cho ADMIN
                        .requestMatchers("/api/demo/admin")
                        .hasRole("ADMIN")

                        // Các API còn lại  Phải đăng nhập
                        .anyRequest()
                        .authenticated()
                )

                // 4. JWT FILTER
                .addFilterBefore(
                        jwtAuthenticationFilter,
                        UsernamePasswordAuthenticationFilter.class
                )

                // 5. TẮT BASIC AUTHENTICATION
                .httpBasic(httpBasic ->
                        httpBasic.disable()
                );
        return http.build();
    }

    // PASSWORD ENCODER
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    // AUTHENTICATION MANAGER
    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration configuration
    ) throws Exception {
        return configuration.getAuthenticationManager();
    }
}

6. XỬ LÝ 401 Unauthorized

Trong quá trình xác thực JWT, không phải Request nào gửi lên Server cũng chứa một JWT hợp lệ.

Client có thể:

  • Không gửi Token.
  • Gửi Token sai định dạng.
  • Gửi Token đã hết hạn.
  • Gửi Token bị thay đổi.
  • Gửi Token có chữ ký không hợp lệ.
  • Không thể tạo Authentication.

Trong những trường hợp này, Spring Security cần xác định rằng:

Request hiện tại chưa được xác thực hợp lệ.

Khi đó, HTTP Status Code thường được sử dụng là:

401 Unauthorized

Có thể hình dung tổng quát:

Client
   │
   │ Request + JWT
   ▼
JwtAuthenticationFilter
   │
   ▼
Kiểm tra JWT
   │
   ├── JWT hợp lệ
   │       ↓
   │   Authentication
   │       ↓
   │   SecurityContext
   │
   └── JWT không hợp lệ
           ↓
      Không Authentication
           ↓
 AuthenticationEntryPoint
           ↓
     401 Unauthorized

6.1. Request không có Token

6.1.1. Trường hợp không có Token

Giả sử chúng ta có API:

HTTP
GET /api/demo/user

và trong SecurityConfig:

Java
.requestMatchers("/api/demo/user")
.hasRole("USER")

Điều này có nghĩa API yêu cầu người dùng phải:

  1. Được xác thực.
  2. Có ROLE_USER.

Nhưng Client lại gửi Request:

HTTP
GET /api/demo/user

mà không có:

HTTP
Authorization: Bearer <token>

Khi đó Server không có thông tin xác thực của người dùng.

Flow:

Client
  │
  │ GET /api/demo/user
  │
  │ Không có Authorization Header
  ▼
Security Filter Chain
  │
  ▼
JwtAuthenticationFilter
  │
  ▼
Không có JWT
  │
  ▼
Không tạo Authentication
  │
  ▼
API yêu cầu Authentication
  │
  ▼
401 Unauthorized

6.1.2. Kiểm tra Header trong Filter

Trong JwtAuthenticationFilter, chúng ta thường lấy Header:

Java
String authHeader =
        request.getHeader("Authorization");

Nếu Client không gửi Header:

authHeader == null

Filter không có JWT để xác thực.

Ví dụ:

Java
if (authHeader == null) {
    filterChain.doFilter(request, response);
    return;
}

Request được cho đi tiếp.

Sau đó Spring Security sẽ kiểm tra:

Có Authentication không?

Nếu không có mà API yêu cầu đăng nhập:

401 Unauthorized

6.2. Token không hợp lệ

6.2.1. Token không hợp lệ là gì?

Token không hợp lệ là Token mà Server không thể xác minh hoặc không thể sử dụng để tạo Authentication hợp lệ.

Ví dụ:

HTTP
Authorization: Bearer abc.def.xyz

nhưng Token này không phải JWT hợp lệ.

Hoặc JWT có thể đã bị thay đổi:

JWT ban đầu
     ↓
Payload bị sửa
     ↓
Signature không còn khớp

6.2.2. Một số nguyên nhân

JWT có thể không hợp lệ vì:

- Sai cấu trúc JWT
- Sai Signature
- Sai Secret Key
- Token bị sửa
- Token bị hỏng
- Không thể parse Token
- Token hết hạn

Khi đó Filter không được tạo Authentication dựa trên Token đó.

6.2.3. Flow

Request
   ↓
Bearer <JWT>
   ↓
JwtAuthenticationFilter
   ↓
Validate JWT
   ↓
JWT không hợp lệ
   ↓
Không có Authentication hợp lệ
   ↓
401 Unauthorized

Điểm quan trọng: Không được tạo Authentication trước khi JWT được xác thực.

Sai:

JWT
 ↓
Lấy username
 ↓
Tạo Authentication

Đúng:

JWT
 ↓
Validate
 ↓
Hợp lệ
 ↓
Lấy username
 ↓
Load UserDetails
 ↓
Tạo Authentication

6.3. Token hết hạn

6.3.1. JWT có thời gian hết hạn

JWT thường chứa Claim:

JSON
{
    "sub": "admin",
    "exp": 1780000000
}

Trong đó:

exp

là thời điểm Token hết hạn.

Ví dụ:

Token được tạo lúc: 10:00
Thời gian sống:     15 phút
Hết hạn lúc:        10:15

Sau 10:15:

JWT
 ↓
Kiểm tra expiration
 ↓
Đã hết hạn
 ↓
JWT không hợp lệ

6.3.2. Tại sao Token hết hạn dẫn đến 401?

JWT hết hạn không còn là thông tin xác thực hợp lệ.

Ví dụ:

Client
  ↓
Bearer <JWT hết hạn>
  ↓
Server kiểm tra
  ↓
Expired
  ↓
Không Authentication
  ↓
401 Unauthorized

401 ở đây có ý nghĩa:

Server không có một thông tin xác thực hợp lệ để xác định Client.

6.3.3. Refresh Token

Trong hệ thống thực tế, khi Access Token hết hạn, ứng dụng có thể sử dụng Refresh Token:

Access Token hết hạn
        ↓
Refresh Token
        ↓
Server cấp Access Token mới
        ↓
Client gọi API lại

Nếu ứng dụng chưa triển khai Refresh Token thì người dùng thường phải đăng nhập lại.

6.4. Token sai chữ ký

6.4.1. JWT Signature

JWT có cấu trúc:

Header.Payload.Signature

Ví dụ:

JWT
eyJhbGciOiJIUzI1NiJ9
.
eyJzdWIiOiJhZG1pbiJ9
.
abc123xyz

Trong đó phần cuối:

Signature

dùng để xác minh JWT.

6.4.2. Secret Key

Khi tạo JWT, Server sử dụng Secret Key để tạo Signature.

Có thể hình dung:

Header
   +
Payload
   +
Secret Key
   ↓
Signature

Khi nhận JWT, Server sử dụng Secret Key để kiểm tra lại.

6.4.3. JWT bị sửa

Giả sử JWT ban đầu chứa:

JSON
{
    "sub": "user",
    "role": "ROLE_USER"
}

Kẻ xấu sửa thành:

JSON
{
    "sub": "admin",
    "role": "ROLE_ADMIN"
}

Nhưng Signature cũ vẫn được giữ nguyên.

Server kiểm tra:

Payload mới
    +
Secret Key
    ↓
Signature mới

Kết quả:

Signature mới
      ≠
Signature trong JWT

JWT bị coi là không hợp lệ.

Flow:

JWT
 ↓
Kiểm tra Signature
 ↓
Signature sai
 ↓
JWT không hợp lệ
 ↓
Không tạo Authentication
 ↓
401 Unauthorized

6.5. Authentication thất bại

6.5.1. Authentication là gì?

Authentication là quá trình xác định:

User hiện tại là ai?

Trong JWT Flow:

JWT
 ↓
Username
 ↓
UserDetails
 ↓
Authentication

Nếu quá trình này thất bại, Spring Security không thể xác định User hợp lệ.

6.5.2. Những trường hợp Authentication thất bại

Có thể xảy ra:

Không có JWT
      ↓
Không Authentication

hoặc:

JWT không hợp lệ
      ↓
Không Authentication

hoặc:

JWT hết hạn
      ↓
Không Authentication

hoặc:

JWT sai chữ ký
      ↓
Không Authentication

Khi Request truy cập tài nguyên yêu cầu Authentication:

Không có Authentication hợp lệ
          ↓
AuthenticationEntryPoint
          ↓
401 Unauthorized

6.5.3. Authentication khác Authorization

Hai khái niệm này cần phân biệt rõ.

Khái niệm Câu hỏi Ví dụ
Authentication Người dùng là ai? User = admin
Authorization Người dùng có quyền gì? ROLE_ADMIN → Có quyền truy cập API Admin

Do đó:

Authentication
      ↓
"Bạn là ai?"

Authorization
      ↓
"Bạn được phép làm gì?"

6.6. AuthenticationEntryPoint

6.6.1. AuthenticationEntryPoint là gì?

AuthenticationEntryPoint là thành phần được Spring Security sử dụng khi Request cần Authentication nhưng người dùng chưa được xác thực hợp lệ.

Có thể hiểu đơn giản: AuthenticationEntryPoint là nơi xử lý tình huống Authentication không tồn tại hoặc không hợp lệ và cần trả về 401 Unauthorized.

Flow:

Request
   ↓
API yêu cầu Authentication
   ↓
Authentication không hợp lệ
   ↓
AuthenticationEntryPoint
   ↓
401 Unauthorized

6.6.2. Vì sao cần AuthenticationEntryPoint?

Nếu không tự cấu hình, Spring Security có thể sử dụng cơ chế xử lý mặc định.

Đối với REST API, chúng ta thường muốn trả về JSON rõ ràng:

JSON
{
    "status": 401,
    "message": "Unauthorized"
}

Frontend có thể dựa vào HTTP Status 401 để biết:

Access Token không còn hợp lệ
        ↓
Xử lý đăng nhập / refresh token

6.6.3. Tạo JwtAuthenticationEntryPoint

JwtAuthenticationEntryPoint.java
package com.example.security.security;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import org.springframework.security.core.AuthenticationException;
import org.springframework.security.web.AuthenticationEntryPoint;

import org.springframework.stereotype.Component;

import java.io.IOException;

@Component
public class JwtAuthenticationEntryPoint
        implements AuthenticationEntryPoint {

    @Override
    public void commence(
            HttpServletRequest request,
            HttpServletResponse response,
            AuthenticationException authException
    ) throws IOException {

        response.setStatus(
                HttpServletResponse.SC_UNAUTHORIZED
        );

        response.setContentType("application/json");

        response.getWriter().write("""
                {
                    "status": 401,
                    "message": "Unauthorized"
                }
                """);
    }
}

6.6.4. Giải thích commence()

Method:

Java
commence()

là method Spring Security gọi khi cần xử lý Authentication Failure.

Nó nhận:

  • HttpServletRequest request – HTTP Request hiện tại.
  • HttpServletResponse response – HTTP Response sẽ trả về Client.
  • AuthenticationException authException – thông tin liên quan đến lỗi Authentication.

package com.example.security.config;

import com.example.security.security.JwtAuthenticationFilter;
import com.example.security.security.JwtAuthenticationEntryPoint;

import lombok.RequiredArgsConstructor;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;

import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;

import org.springframework.security.config.http.SessionCreationPolicy;

import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;


@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    private final JwtAuthenticationEntryPoint
            jwtAuthenticationEntryPoint;


    @Bean
    public SecurityFilterChain securityFilterChain(
            HttpSecurity http
    ) throws Exception {

        http

                // =============================================
                // 1. Tắt CSRF
                // =============================================

                .csrf(csrf -> csrf.disable())


                // =============================================
                // 2. Stateless
                // =============================================

                .sessionManagement(session ->
                        session.sessionCreationPolicy(
                                SessionCreationPolicy.STATELESS
                        )
                )


                // =============================================
                // 3. Authorization
                // =============================================

                .authorizeHttpRequests(auth -> auth

                        // Login / Register
                        .requestMatchers("/api/auth/**")
                        .permitAll()

                        // USER
                        .requestMatchers("/api/demo/user")
                        .hasRole("USER")

                        // ADMIN
                        .requestMatchers("/api/demo/admin")
                        .hasRole("ADMIN")

                        // Các API khác
                        .anyRequest()
                        .authenticated()
                )


                // =============================================
                // 4. Xử lý Authentication Failure
                // =============================================

                .exceptionHandling(exception ->
                        exception.authenticationEntryPoint(
                                jwtAuthenticationEntryPoint
                        )
                )


                // =============================================
                // 5. JWT Filter
                // =============================================

                .addFilterBefore(
                        jwtAuthenticationFilter,
                        UsernamePasswordAuthenticationFilter.class
                )


                // =============================================
                // 6. Tắt Basic Authentication
                // =============================================

                .httpBasic(httpBasic ->
                        httpBasic.disable()
                );


        return http.build();
    }


    @Bean
    public PasswordEncoder passwordEncoder() {

        return new BCryptPasswordEncoder();
    }


    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration configuration
    ) throws Exception {

        return configuration.getAuthenticationManager();
    }
}

JwtService.java
package com.example.project.service;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;

import java.util.Date;
import java.util.function.Function;


@Service
public class JwtService {

    @Value("${jwt.secret-key}")
    private String secretKey;

    @Value("${jwt.expiration}")
    private long expiration;


    // =====================================================
    // TẠO JWT
    // =====================================================

    public String generateToken(
            UserDetails userDetails
    ) {

        return Jwts.builder()

                .subject(
                        userDetails.getUsername()
                )

                .claim(
                        "role",
                        userDetails.getAuthorities()
                                .stream()
                                .findFirst()
                                .map(
                                        GrantedAuthority::getAuthority
                                )
                                .orElse("")
                )

                .issuedAt(new Date())

                .expiration(
                        new Date(
                                System.currentTimeMillis()
                                        + expiration
                        )
                )

                .signWith(getKey())

                .compact();
    }


    // =====================================================
    // LẤY USERNAME TỪ JWT
    // =====================================================

    public String extractUsername(
            String token
    ) {

        return extractClaim(
                token,
                Claims::getSubject
        );
    }


    // =====================================================
    // LẤY CLAIM
    // =====================================================

    public <T> T extractClaim(
            String token,
            Function<Claims, T> claimsResolver
    ) {

        Claims claims = extractAllClaims(token);

        return claimsResolver.apply(claims);
    }


    // =====================================================
    // LẤY TOÀN BỘ CLAIM
    // =====================================================

    private Claims extractAllClaims(
            String token
    ) {

        return Jwts.parser()

                .verifyWith(getKey())

                .build()

                .parseSignedClaims(token)

                .getPayload();
    }


    // =====================================================
    // KIỂM TRA JWT
    // =====================================================

    public boolean isTokenValid(
            String token,
            UserDetails userDetails
    ) {

        final String username =
                extractUsername(token);

        return username.equals(
                    userDetails.getUsername()
                )
                && !isTokenExpired(token);
    }


    // =====================================================
    // KIỂM TRA HẾT HẠN
    // =====================================================

    private boolean isTokenExpired(
            String token
    ) {

        return extractExpiration(token)
                .before(new Date());
    }


    private Date extractExpiration(
            String token
    ) {

        return extractClaim(
                token,
                Claims::getExpiration
        );
    }


    // =====================================================
    // TẠO SECRET KEY
    // =====================================================

    private SecretKey getKey() {

        return Keys.hmacShaKeyFor(
                Decoders.BASE64.decode(
                        secretKey
                )
        );
    }
}

7.8. JwtAuthenticationFilter.java

Đây là thành phần quan trọng để xử lý JWT ở mỗi Request.

JwtAuthenticationFilter.java
package com.example.project.security;

import com.example.project.service.JwtService;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import lombok.RequiredArgsConstructor;

import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;

import org.springframework.security.core.context.SecurityContextHolder;

import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;

import org.springframework.security.web.authentication.WebAuthenticationDetailsSource;

import org.springframework.stereotype.Component;

import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;


@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter
        extends OncePerRequestFilter {

    private final JwtService jwtService;

    private final UserDetailsService userDetailsService;


    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain
    ) throws ServletException, IOException {


        // =================================================
        // 1. LẤY AUTHORIZATION HEADER
        // =================================================

        String authHeader =
                request.getHeader("Authorization");


        // =================================================
        // 2. KIỂM TRA HEADER
        // =================================================

        if (
                authHeader == null
                        ||
                !authHeader.startsWith("Bearer ")
        ) {

            filterChain.doFilter(
                    request,
                    response
            );

            return;
        }


        // =================================================
        // 3. TÁCH JWT
        // =================================================

        String jwt =
                authHeader.substring(7);


        try {

            // =============================================
            // 4. LẤY USERNAME TỪ JWT
            // =============================================

            String username =
                    jwtService.extractUsername(jwt);


            // =============================================
            // 5. KIỂM TRA SECURITY CONTEXT
            // =============================================

            if (
                    username != null
                            &&
                    SecurityContextHolder
                            .getContext()
                            .getAuthentication()
                            == null
            ) {


                // =========================================
                // 6. LOAD USER DETAILS
                // =========================================

                UserDetails userDetails =
                        userDetailsService
                                .loadUserByUsername(
                                        username
                                );


                // =========================================
                // 7. VALIDATE JWT
                // =========================================

                if (
                        jwtService.isTokenValid(
                                jwt,
                                userDetails
                        )
                ) {


                    // =====================================
                    // 8. TẠO AUTHENTICATION
                    // =====================================

                    UsernamePasswordAuthenticationToken
                            authentication =
                            new UsernamePasswordAuthenticationToken(
                                    userDetails,
                                    null,
                                    userDetails.getAuthorities()
                            );


                    // =====================================
                    // 9. GẮN REQUEST DETAILS
                    // =====================================

                    authentication
                            .setDetails(
                                    new WebAuthenticationDetailsSource()
                                            .buildDetails(request)
                            );


                    // =====================================
                    // 10. ĐƯA VÀO SECURITY CONTEXT
                    // =====================================

                    SecurityContextHolder
                            .getContext()
                            .setAuthentication(
                                    authentication
                            );
                }
            }

        } catch (Exception e) {

            // JWT không hợp lệ
            // Không tạo Authentication

        }


        // =================================================
        // 11. CHO REQUEST ĐI TIẾP
        // =================================================

        filterChain.doFilter(
                request,
                response
        );
    }
}

import org.springframework.security.crypto.password.PasswordEncoder;

import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@EnableWebSecurity
@RequiredArgsConstructor

                )

                        )
                )

                        .authenticated()
                )

                        exception.authenticationEntryPoint(

                        jwtAuthenticationFilter,
                        UsernamePasswordAuthenticationFilter.class
                )

                        httpBasic.disable()
                );
