TỔNG QUAN VỀ OAUTH2 RESOURCE SERVER

Nếu chúng ta đã xây dựng cơ chế JWT Authentication theo hướng tự xử lý JWT bằng JwtAuthenticationFilter.

Với cách tiếp cận đó, chúng ta phải tự thực hiện khá nhiều công việc:

Quy trình tự xử lý JWT
HTTP Request
      ↓
Đọc Authorization Header
      ↓
Lấy Bearer Token
      ↓
Tách JWT
      ↓
Validate JWT
      ↓
Lấy username
      ↓
Load UserDetails
      ↓
Tạo Authentication
      ↓
SecurityContext

Cách làm này giúp chúng ta hiểu rất rõ JWT Authentication hoạt động như thế nào. Tuy nhiên, trong thực tế Spring Security đã cung cấp sẵn cơ chế xử lý JWT thông qua OAuth2 Resource Server.

Thay vì tự viết toàn bộ Filter, chúng ta có thể cấu hình:

Cấu hình OAuth2 Resource Server
.oauth2ResourceServer(oauth2 →
    oauth2.jwt(
        Customizer.withDefaults()
    )
)

Khi đó, Spring Security sẽ đảm nhiệm phần lớn quá trình xử lý và xác thực JWT.

1.1. OAuth2 Resource Server là gì?

1.1.1. Khái niệm Resource Server

Resource Server là một ứng dụng Backend/API có nhiệm vụ cung cấp và bảo vệ các tài nguyên (resources).

Ví dụ một hệ thống có các API:

Ví dụ API
GET /api/users
GET /api/users/profile
POST /api/products
PUT /api/products/10
DELETE /api/products/10

Các API này chính là những resources mà Client muốn truy cập.

Backend sẽ chịu trách nhiệm:

  • nhận request;
  • xác thực người dùng;
  • kiểm tra Access Token;
  • xác định request có thông tin Authentication hợp lệ hay không;
  • sau đó cho phép request tiếp tục xử lý.

Có thể hình dung:

Luồng Client → Resource Server
Client
   │
   │ Request + Access Token
   ▼
Resource Server
   │
   │ Xác thực Token
   ▼
Protected Resource

Ví dụ:

Ví dụ thực tế
Frontend
   │
   │ GET /api/users/profile
   │ Authorization: Bearer <JWT>
   ▼
Spring Boot Backend
   │
   ▼
Kiểm tra JWT
   │
   ▼
API /api/users/profile

1.1.2. Resource Server trong OAuth2

Trong kiến trúc OAuth2, thường có thể xuất hiện nhiều thành phần khác nhau.

Một cách hình dung đơn giản:

Kiến trúc OAuth2 cơ bản
┌──────────────┐
│ Client │
│ │
│ Frontend/App │
└──────┬───────┘
       │
       │ Access Token
       ▼
┌──────────────────┐
│ Resource Server │
│ │
│ Spring Boot API │
└────────┬─────────┘
             │
             ▼
    Protected Data

Client là bên gọi API.

Resource Server là Backend cung cấp API và bảo vệ các API đó.

Access Token là thông tin được Client gửi kèm request để chứng minh rằng request đã được xác thực.

Trong trường hợp của chúng ta, JWT có thể được sử dụng làm Access Token.

1.1.3. OAuth2 Resource Server trong Spring Security

Spring Security cung cấp module OAuth2 Resource Server để giúp ứng dụng xử lý các request có Access Token.

Đối với JWT, chúng ta có thể cấu hình:

Cấu hình Resource Server với JWT
http
    .oauth2ResourceServer(oauth2 →
        oauth2.jwt(
            Customizer.withDefaults()
        )
    );

Cấu hình này nói với Spring Security rằng:

Ứng dụng này hoạt động như một OAuth2 Resource Server và sử dụng JWT để xác thực Bearer Token.

Từ đây, Spring Security có thể xử lý JWT thay cho việc chúng ta phải tự xây dựng toàn bộ cơ chế Filter.

1.4. Vì sao sử dụng OAuth2 Resource Server?

Nếu tự viết JWT Filter, chúng ta phải tự xử lý rất nhiều công việc.

Ví dụ trong cách cũ:

Đọc Authorization Header
String authHeader =
        request.getHeader("Authorization");

Sau đó kiểm tra:

Kiểm tra Bearer Token
if (authHeader == null
        || !authHeader.startsWith("Bearer ")) {
    filterChain.doFilter(request, response);
    return;
}

Tách token:

Tách JWT từ Header
String jwt =
        authHeader.substring(7);

Lấy username:

Extract username từ JWT
String username =
        jwtService.extractUsername(jwt);

Load UserDetails:

Load UserDetails từ username
UserDetails userDetails =
        userDetailsService
                .loadUserByUsername(username);

Validate:

Validate JWT
jwtService.isTokenValid(
    jwt,
    userDetails
);

Sau đó tạo Authentication và đưa vào SecurityContext. Đây chính là chuỗi xử lý mà phần Filter phải xây dựng.

2.1. Bearer Token là gì?

2.1.1. Khái niệm Bearer Token

Bearer Token là một loại access token mà bên nào sở hữu (bear) token thì có thể sử dụng token đó để gửi request đến Resource Server.

Nói đơn giản:

Ai có Bearer Token hợp lệ thì có thể sử dụng token đó để xác thực request.

Ví dụ Client có token:

Ví dụ JWT Token
eyJhbGciOiJIUzI1NiJ9...

Client gửi:

Gửi Bearer Token trong Header
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Resource Server nhận token và xác thực nó.

2.1.2. Tại sao gọi là "Bearer"?

Bearer có nghĩa gần giống như "người mang / người sở hữu".

Ý tưởng ở đây là:

Ý nghĩa của Bearer
Có Token
    ↓
Mang Token đi gửi Request
    ↓
Resource Server xác thực Token

Không cần gửi lại:

username
password

ở mỗi request.

Thay vào đó:

Luồng sử dụng Bearer Token
Login
   ↓
Username + Password
   ↓
Access Token
   ↓
Các request tiếp theo
   ↓
Bearer Token

2.1.3. Bearer Token có phải luôn là JWT không?

Không.

Đây là điểm rất quan trọng.

Bearer Token mô tả cách Token được sử dụng, không quy định Token phải có định dạng JWT.

Có thể hình dung:

Phân loại Bearer Token
Bearer Token
     │
     ├── JWT
     │
     └── Opaque Token

Trong bài này, chúng ta sử dụng:

Bearer Token = JWT Access Token

Do đó request thường có dạng:

Request với JWT Bearer Token
Authorization: Bearer <JWT>

2.2. Authorization Header

2.2.1. Authorization Header là gì?

HTTP Request có thể chứa nhiều Header.

Ví dụ:

HTTP Request với Authorization Header
GET /api/users/profile HTTP/1.1
Host: localhost:8080
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Trong đó:

Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

là Authorization Header.

Header này được sử dụng để gửi thông tin xác thực từ Client đến Server.

2.2.2. Cấu trúc Authorization Header

Cấu trúc cơ bản:

Cấu trúc Authorization Header
Authorization: <scheme> <credentials>

Đối với Bearer Token:

Bearer Token trong Authorization Header
Authorization: Bearer <token>

Ví dụ:

Authorization: Bearer abc123xyz

Trong bài của chúng ta:

Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

Có thể chia thành:

Cấu trúc chi tiết
Authorization
      │
      └── Bearer
              │
              └── JWT Token

2.2.3. Vì sao phải có Bearer?

Spring Security cần biết token trong Header đang được gửi theo cơ chế nào.

Ví dụ:

Authorization: Bearer <JWT>

Từ khóa:

Bearer

cho Spring Security biết rằng phần phía sau là Bearer Token.

Có thể hình dung:

Phân tích Authorization Header
Authorization Header
        │
        ▼
Bearer <Token>
  │       │
  │       └── Token
  │
  └── Scheme

Sau khi thêm OAuth2 Resource Server, SecurityConfig có thể có dạng:

package com.example.demo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(
        HttpSecurity http
    ) throws Exception {

        http

            // REST API không sử dụng CSRF
            .csrf(csrf → csrf.disable())

            // JWT Authentication là Stateless
            .sessionManagement(session →
                session.sessionCreationPolicy(
                    SessionCreationPolicy.STATELESS
                )
            )

            // Phân quyền endpoint
            .authorizeHttpRequests(auth → auth

                // API authentication không cần JWT
                .requestMatchers("/api/auth/**")
                .permitAll()

                // Các API còn lại cần Authentication
                .anyRequest()
                .authenticated()
            )

            // OAuth2 Resource Server sử dụng JWT
            .oauth2ResourceServer(oauth2 →
                oauth2.jwt(Customizer.withDefaults())
            );

        return http.build();
    }
}

import com.example.security2.entity.User;
import com.example.security2.repository.UserRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class CustomUserDetailsService
        implements UserDetailsService {

    private final UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String username)
            throws UsernameNotFoundException {

        User user = userRepository
                .findByUsername(username)
                .orElseThrow(() ->
                        new UsernameNotFoundException(
                                "User not found"
                        )
                );

        return org.springframework.security.core.userdetails.User
                .withUsername(user.getUsername())
                .password(user.getPassword())
                .roles(user.getRole())
                .build();
    }
}

Giải thích:

  • User.withUsername() – Tạo đối tượng UserDetails từ User trong DB
  • .roles(user.getRole()) – Gán Role cho User

10. JwtService

Đây là class chuyên tạo JWT.

JwtService.java 
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;
import java.util.Date;

@Service
public class JwtService {

    @Value("${jwt.secret-key}")
    private String secretKey;

    @Value("${jwt.expiration}")
    private long expiration;

    public String generateToken(UserDetails userDetails) {

        return Jwts.builder()

                // Subject
                .subject(userDetails.getUsername())

                // Custom Claim
                .claim(
                        "role",
                        userDetails.getAuthorities()
                                .stream()
                                .findFirst()
                                .map(GrantedAuthority::getAuthority)
                                .orElse("")
                )

                // Thời điểm tạo Token
                .issuedAt(new Date())

                // Thời điểm hết hạn
                .expiration(
                        new Date(
                                System.currentTimeMillis()
                                        + expiration
                        )
                )

                // Ký JWT
                .signWith(getKey())

                // Tạo JWT String
                .compact();
    }

    private SecretKey getKey() {

        return Keys.hmacShaKeyFor(
                Decoders.BASE64.decode(secretKey)
        );
    }
}
Giải thích JwtService:
  • @Value("${jwt.secret-key}") – Lấy Secret Key từ application.yml
  • @Value("${jwt.expiration}") – Lấy thời gian hết hạn từ application.yml
  • subject(userDetails.getUsername()) – Đặt username vào Subject của JWT
  • claim("role", ...) – Thêm Role vào Custom Claim
  • issuedAt(new Date()) – Thời gian tạo Token
  • expiration(...) – Thời gian hết hạn = hiện tại + expiration
  • signWith(getKey()) – Ký JWT bằng Secret Key
  • compact() – Tạo JWT String
  • getKey() – Chuyển Secret Key từ Base64 String → SecretKey

import com.example.security2.DTO.repquert.LoginRequest;
import com.example.security2.DTO.response.LoginResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class AuthService {

    private final AuthenticationManager authenticationManager;

    private final JwtService jwtService;

    public LoginResponse login(LoginRequest request) {

        Authentication authentication =
                authenticationManager.authenticate(
                        new UsernamePasswordAuthenticationToken(
                                request.getUsername(),
                                request.getPassword()
                        )
                );

        UserDetails userDetails =
                (UserDetails) authentication.getPrincipal();

        String token = jwtService.generateToken(userDetails);

        return new LoginResponse(token);
    }
}

  • authentication.getPrincipal() – Lấy UserDetails đã được xác thực

SecurityConfig.java 
package com.example.demosecurity.config;

import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;
import lombok.RequiredArgsConstructor;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;

import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;

import org.springframework.security.oauth2.jwt.JwtDecoder;
import org.springframework.security.oauth2.jwt.NimbusJwtDecoder;

import org.springframework.security.web.SecurityFilterChain;

import javax.crypto.SecretKey;

@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    @Value("${jwt.secret-key}")
    private String secretKeyValue;

    @Bean
    public SecurityFilterChain securityFilterChain(
            HttpSecurity http
    ) throws Exception {

        http
                .csrf(csrf -> csrf.disable())

                .sessionManagement(session ->
                        session.sessionCreationPolicy(
                                SessionCreationPolicy.STATELESS
                        )
                )

                .authorizeHttpRequests(auth -> auth
                        .requestMatchers(
                                "/api/auth/login"
                        ).permitAll()

                        .anyRequest()
                        .authenticated()
                )

                // OAuth2 Resource Server sử dụng JWT
                .oauth2ResourceServer(oauth2 ->
                        oauth2.jwt(Customizer.withDefaults())
                );

        return http.build();
    }

    @Bean
    public JwtDecoder jwtDecoder() {

        SecretKey secretKey = Keys.hmacShaKeyFor(
                Decoders.BASE64.decode(secretKeyValue)
        );

        return NimbusJwtDecoder
                .withSecretKey(secretKey)
                .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {

        return new BCryptPasswordEncoder();
    }

    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration configuration
    ) throws Exception {

        return configuration.getAuthenticationManager();
    }
}
Giải thích SecurityConfig:
  • @EnableWebSecurity – Kích hoạt Spring Security
  • csrf().disable() – Tắt CSRF (phù hợp với REST API)
  • sessionCreationPolicy(SessionCreationPolicy.STATELESS) – Không tạo Session (Stateless)
  • requestMatchers("/api/auth/login").permitAll() – Cho phép truy cập login không cần xác thực
  • anyRequest().authenticated() – Tất cả API khác cần xác thực
  • BCryptPasswordEncoder – Mã hóa password
  • authenticationManager – Bean để xác thực
