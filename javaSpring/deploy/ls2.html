1. Tổng quan về triển khai ứng dụng

1.1. Deploy là gì?

Trong quá trình phát triển phần mềm, lập trình viên thường chạy Spring Boot trên máy tính cá nhân, chẳng hạn tại địa chỉ:

http://localhost:8080

Địa chỉ này chỉ có thể được truy cập trong môi trường phù hợp trên máy tính đang chạy ứng dụng. Người dùng ở thiết bị khác không thể mặc nhiên truy cập ứng dụng qua địa chỉ localhost của máy lập trình viên.

Deploy là quá trình đưa ứng dụng từ môi trường phát triển lên máy chủ hoặc nền tảng đám mây để người dùng có thể truy cập qua Internet.

Ví dụ, sau khi deploy thành công, ứng dụng có thể có địa chỉ:

https://demodeploy.onrender.com

Đây là URL minh họa; URL thực tế do Render cấp khi tạo dịch vụ.

Ví dụ cấu hình Local:

Properties
spring.datasource.url=jdbc:mysql://localhost:3306/quanlybanhang
spring.datasource.username=root

Khi triển khai lên Render, không thể tiếp tục sử dụng localhost:3306 để kết nối đến MySQL trên máy tính cá nhân.

Lý do: bên trong môi trường chạy ứng dụng trên Render, localhost trỏ đến chính môi trường đó, không phải máy tính cá nhân của lập trình viên.

2.2. JAR là gì?

JAR (Java Archive) là gói chứa các thành phần cần thiết của ứng dụng Java. Với Spring Boot, file JAR được đóng gói để có thể khởi chạy bằng lệnh:

Bash
java -jar app.jar

Tuy nhiên, bài học này sử dụng Docker để chạy file JAR trên Render. Vì vậy, file JAR sẽ được đưa vào Docker image.

2.3. Dockerfile là gì?

Dockerfile là file chứa các chỉ dẫn để Docker tạo image.

Ví dụ:

Dockerfile
FROM eclipse-temurin:25-jre

WORKDIR /app

COPY app.jar app.jar

ENTRYPOINT ["java", "-jar", "app.jar"]

Ý nghĩa:

  • FROM: chọn image nền có Java Runtime.
  • WORKDIR: thiết lập thư mục làm việc trong container.
  • COPY: sao chép file JAR vào container.
  • ENTRYPOINT: xác định lệnh khởi động ứng dụng.

Lưu ý: Phiên bản Java trong Docker phải tương thích với phiên bản Java dùng để biên dịch dự án. Nếu dự án được biên dịch bằng Java 17, nên chọn image Java 17; nếu dùng Java 25, chọn image tương ứng.

2.4. Environment Variables là gì?

Environment Variables là các biến môi trường dùng để truyền cấu hình cho ứng dụng mà không cần ghi trực tiếp giá trị vào mã nguồn.

Ví dụ:

Properties
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}

Khi chạy trên Render, Spring Boot lấy giá trị từ các biến DB_URL, DB_USERNAME và DB_PASSWORD đã được khai báo trong phần Environment.

Cách này giúp tránh đưa mật khẩu database lên GitHub.

3. Tạo MySQL service

Bước 3.1. Đăng ký và đăng nhập

Truy cập trang chủ Aiven:

Mở Aiven Console

Đăng nhập hoặc tạo tài khoản mới.

Bước 3.2. Tạo dịch vụ MySQL

Trong giao diện Aiven:

  1. Chọn tạo service mới.
  2. Chọn loại dịch vụ MySQL.
  3. Chọn gói dịch vụ phù hợp với ngân sách.
  4. Chọn khu vực triển khai, ưu tiên khu vực gần ứng dụng nếu có thể.
  5. Đặt tên service, ví dụ mysql-quanlybanhang.
  6. Nhấn tạo service và chờ dịch vụ khởi tạo.

Lưu ý về chi phí: Gói miễn phí và điều kiện sử dụng của Aiven có thể thay đổi theo thời điểm, tài khoản và khu vực. Hãy kiểm tra giá hiển thị trong Console trước khi tạo dịch vụ; không mặc định rằng mọi tài khoản đều có MySQL miễn phí.

4. Lấy thông tin kết nối MySQL

Sau khi service hoạt động, mở trang Overview hoặc phần Connection information.

Thông tin cần ghi lại:

4.1. Vì sao port không phải 3306?

MySQL thường sử dụng port 3306 khi chạy trên máy tính cá nhân. Tuy nhiên, dịch vụ MySQL được quản lý trên Aiven có thể cấp một port khác, chẳng hạn 22510.

Nếu cấu hình sai port, ứng dụng có thể không kết nối được database.

4.2. Tạo database riêng

Trong Aiven, mở mục Databases và tạo database, ví dụ:

quanlybanhang

Database này sẽ chứa các bảng của dự án.

Nếu bạn đã có file SQL ở máy tính cá nhân, cần nhập dữ liệu và cấu trúc bảng lên Aiven. Tạo database trên Aiven không tự động sao chép dữ liệu từ MySQL Workbench ở máy tính cá nhân.

Có thể sử dụng MySQL Workbench để kết nối đến Aiven và import file .sql.

5. Cấu hình mạng và SSL

5.1. Cho phép ứng dụng kết nối

Kiểm tra phần Networking hoặc IP filter của dịch vụ Aiven.

Cần đảm bảo kết nối từ Render đến Aiven được cho phép theo cơ chế mạng mà gói dịch vụ hỗ trợ.

Không nên mặc định thêm 0.0.0.0/0 nếu không cần thiết. Cấu hình này cho phép mọi địa chỉ IP có thể thử kết nối đến dịch vụ, làm tăng nguy cơ bị dò quét. Nếu phải sử dụng để kiểm thử, hãy kết hợp mật khẩu mạnh, SSL và các giới hạn truy cập phù hợp.

5.2. SSL là gì?

SSL/TLS mã hóa dữ liệu truyền giữa ứng dụng Spring Boot và máy chủ MySQL, giảm nguy cơ thông tin bị đọc trộm trên đường truyền.

Với Aiven, hãy dùng chế độ SSL được dịch vụ yêu cầu. Nếu cần xác minh chứng chỉ máy chủ, hãy cấu hình CA certificate theo tài liệu của Aiven thay vì tắt kiểm tra chứng chỉ.

Ví dụ tham số JDBC thường dùng:

Text
?sslMode=REQUIRED

REQUIRED yêu cầu kết nối SSL, nhưng không tương đương với việc xác minh danh tính máy chủ bằng CA. Khi triển khai thực tế, cần lựa chọn chế độ SSL phù hợp với khả năng hỗ trợ và hướng dẫn hiện hành của Aiven.

PHẦN II. CẤU HÌNH DỰ ÁN SPRING BOOT

6. Tổ chức cấu hình theo Profile

Spring Boot hỗ trợ Profile để sử dụng cấu hình khác nhau tùy môi trường chạy.

Ví dụ:

  • local: chạy trên máy cá nhân.
  • prod: chạy trên môi trường Production.

6.1. Cấu trúc file

src/
└── main/
    └── resources/
        ├── application.properties
        ├── application-local.properties
        └── application-prod.properties

Mỗi file đảm nhiệm một vai trò riêng.

7. Cấu hình application.properties

File này chứa các cấu hình chung, áp dụng cho mọi môi trường.

Properties
spring.application.name=deploy

spring.profiles.active=${SPRING_PROFILES_ACTIVE:local}

server.port=${PORT:8080}

spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.naming.physical-strategy=org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl

Giải thích:

  • spring.application.name: tên ứng dụng.
  • spring.profiles.active: chọn Profile đang hoạt động; mặc định là local.
  • server.port: cổng ứng dụng sử dụng. Render có thể cung cấp biến PORT, vì vậy ứng dụng nên đọc giá trị này.
  • spring.datasource.driver-class-name: tên JDBC driver của MySQL.
  • spring.jpa.hibernate.naming.physical-strategy: chiến lược ánh xạ tên bảng và cột; chỉ giữ cấu hình này nếu dự án thực sự cần.

Không bắt buộc phải tách mọi cấu hình thành ba file. Đây là cách tổ chức dễ học và dễ quản lý khi dự án có nhiều môi trường.

8. Cấu hình application-local.properties

File này dùng khi chạy dự án trên máy tính cá nhân.

Properties
spring.datasource.url=jdbc:mysql://localhost:3306/quanlybanhang?serverTimezone=Asia/Ho_Chi_Minh&characterEncoding=UTF-8
spring.datasource.username=root
spring.datasource.password=${LOCAL_DB_PASSWORD:1234}

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

Giải thích:

  • localhost:3306: địa chỉ MySQL trên máy tính cá nhân.
  • quanlybanhang: tên database.
  • LOCAL_DB_PASSWORD: biến môi trường tùy chọn để lưu mật khẩu MySQL local.
  • ddl-auto=update: cho phép Hibernate cập nhật cấu trúc bảng dựa trên entity.

Trong môi trường học tập, update có thể thuận tiện. Với production, không nên dựa vào Hibernate để tự động thay đổi cấu trúc database một cách thiếu kiểm soát.

9. Cấu hình application-prod.properties

File này dùng khi chạy ứng dụng trên Render.

Properties
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=false
spring.jpa.properties.hibernate.format_sql=true

Ba biến kết nối sẽ được khai báo trên Render:

  • DB_URL: JDBC URL của MySQL Aiven.
  • DB_USERNAME: tên tài khoản database.
  • DB_PASSWORD: mật khẩu database.

Lưu ý: ddl-auto=update phù hợp với một số dự án học tập, nhưng với ứng dụng thực tế nên quản lý schema bằng công cụ migration như Flyway hoặc Liquibase. Nếu database đã được tạo bảng đầy đủ bằng file SQL, hãy kiểm tra entity và schema trước khi bật update.

10. Kiểm tra pom.xml

10.1. MySQL Connector

Đảm bảo dự án có dependency sau:

XML
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

Nếu dự án sử dụng Spring Boot Parent hoặc dependency management, thông thường không cần tự khai báo phiên bản Connector riêng, trừ khi có yêu cầu tương thích đặc biệt.

10.2. Spring Boot Maven Plugin

Đảm bảo có plugin đóng gói Spring Boot:

XML
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>

Nếu thiếu dependency hoặc plugin cần thiết, quá trình đóng gói hoặc khởi chạy ứng dụng có thể thất bại.

PHẦN III. ĐÓNG GÓI SPRING BOOT BẰNG DOCKER

11. Build file JAR

Mở Terminal tại thư mục gốc dự án, nơi có file pom.xml.

Windows

Batch
mvnw.cmd clean package -DskipTests

Nếu dự án không có Maven Wrapper, có thể sử dụng:

Batch
mvn clean package -DskipTests

macOS/Linux

Bash
./mvnw clean package -DskipTests

Nếu thành công, Maven sẽ hiển thị:

BUILD SUCCESS

File JAR thường nằm trong thư mục target.

Ví dụ:

target/deploy-0.0.1-SNAPSHOT.jar

Tên file thực tế phụ thuộc vào artifactId và version trong pom.xml.

11.1. Vì sao dùng -DskipTests?

Tùy chọn này bỏ qua việc chạy test trong quá trình build, giúp build nhanh hơn. Tuy nhiên, nó không đảm bảo ứng dụng hoạt động đúng. Trong quy trình chuyên nghiệp, nên chạy test trước khi triển khai.

12. Đưa JAR vào thư mục gốc

Có thể sao chép JAR vào thư mục gốc dự án và đổi tên thành app.jar.

Cấu trúc sau khi sao chép:

deploy/
├── src/
├── target/
├── app.jar
├── Dockerfile
├── pom.xml
└── .gitignore

Nếu dùng phương án này, cần build lại và sao chép lại app.jar mỗi khi thay đổi source code.

Để tránh quên cập nhật JAR, một lựa chọn khác là để Docker tự build ứng dụng từ source code. Bài này sử dụng cách đóng gói JAR trước để người mới dễ theo dõi.

13. Tạo Dockerfile

Tạo file tên chính xác là Dockerfile, không có phần mở rộng .txt, tại thư mục gốc dự án.

Dockerfile
FROM eclipse-temurin:25-jre

WORKDIR /app

COPY app.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]

Trong ví dụ trên, Java 25 được sử dụng minh họa. Hãy đổi 25-jre thành phiên bản tương thích với dự án của bạn nếu cần.

13.1. Giải thích Dockerfile

Chỉ dẫn Ý nghĩa
FROMChọn image có Java Runtime
WORKDIRTạo/chọn thư mục làm việc
COPYSao chép JAR vào image
EXPOSEKhai báo cổng dự kiến của ứng dụng
ENTRYPOINTChạy ứng dụng khi container khởi động

Điểm cần nhớ: EXPOSE 10000 không tự động khiến Spring Boot lắng nghe trên cổng 10000. Cổng thực tế phải phù hợp với cấu hình server.port và cách Render cấp biến PORT. Vì vậy, ví dụ trên sử dụng EXPOSE 8080, còn Spring Boot vẫn đọc PORT do Render cung cấp.

14. Đưa source code lên GitHub

Nếu dự án chưa có Git repository:

Bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

Nếu repository đã tồn tại, thông thường chỉ cần:

Bash
git add .
git commit -m "Prepare Spring Boot deployment"
git push origin main

Thay USERNAME và REPOSITORY bằng thông tin thực tế.

14.1. Kiểm tra bảo mật trước khi push

Không đưa các thông tin sau lên GitHub công khai:

  • Mật khẩu MySQL.
  • API key và secret.
  • File chứa thông tin bí mật.
  • Các biến môi trường dùng cho Production.

Trong ví dụ giáo trình, file cấu hình Local có mật khẩu minh họa. Khi làm dự án thật, nên chuyển mật khẩu sang biến môi trường và bảo đảm không commit bí mật vào repository.

16. Khai báo biến môi trường

Trong trang Web Service, mở mục Environment và thêm các biến cần thiết.

Key Value
SPRING_PROFILES_ACTIVEprod
DB_URLJDBC URL của MySQL Aiven
DB_USERNAMEUsername Aiven
DB_PASSWORDPassword Aiven

Ví dụ JDBC URL:

Text

Đây chỉ là URL mẫu. Hãy thay host, port và tên database bằng thông tin của dịch vụ thực tế.

16.1. Tại sao phải có SPRING_PROFILES_ACTIVE=prod?

Khi khai báo:

SPRING_PROFILES_ACTIVE=prod

Spring Boot sẽ sử dụng cấu hình chung trong application.properties và nạp thêm cấu hình từ application-prod.properties.

Luồng đọc cấu hình:

SPRING_PROFILES_ACTIVE=prod
        |
        v
application.properties
        |
        v
application-prod.properties
        |
        v
Spring Boot kết nối MySQL Aiven

Nếu không kích hoạt Profile prod, ứng dụng có thể tiếp tục sử dụng cấu hình Local và cố kết nối đến localhost:3306.

16.2. Cách kiểm tra DB_URL

Đảm bảo URL có đủ thành phần:

Text
jdbc:mysql://HOST:PORT/DATABASE?sslMode=REQUIRED

Trong đó:

  • HOST: hostname của Aiven.
  • PORT: port Aiven cấp.
  • DATABASE: tên database thực tế.
  • sslMode: chế độ SSL theo yêu cầu kết nối.

Không nhập nguyên các giá trị minh họa như mysql-xxxxx... vào Render.

17. Deploy ứng dụng

Sau khi lưu biến môi trường:

  1. Kiểm tra branch và cấu hình Docker.
  2. Nhấn tạo Web Service hoặc triển khai bản commit mới nhất.
  3. Mở tab Logs.
  4. Theo dõi quá trình build image và khởi động ứng dụng.
  5. Nếu deploy thất bại, đọc dòng lỗi đầu tiên có ý nghĩa thay vì chỉ xem dòng cuối cùng.

Các dấu hiệu thường gặp khi khởi động thành công:

Tomcat started on port ...
Started DeployApplication in ... seconds

Render có thể hiển thị thông báo dịch vụ hoạt động và URL công khai.

Không nhất thiết Tomcat phải khởi động trên port 10000. Hãy kiểm tra giá trị PORT được Render cung cấp và cấu hình mà ứng dụng thực sự sử dụng.

PHẦN V. KIỂM TRA ỨNG DỤNG SAU KHI DEPLOY

18. Kiểm tra URL Render

Render cấp một URL dạng:

https://ten-dich-vu.onrender.com

Mở URL trên trình duyệt để kiểm tra.

Nếu ứng dụng không khai báo API ở đường dẫn /, việc truy cập URL gốc có thể trả về 404 Not Found. Điều đó chưa đủ để kết luận rằng deploy thất bại.

Hãy kiểm tra một endpoint thực sự có trong dự án, ví dụ:

HTTP
GET https://ten-dich-vu.onrender.com/api/products

Đường dẫn /api/products chỉ là ví dụ; hãy thay bằng endpoint đang tồn tại trong ứng dụng.

19. Kiểm tra bằng Postman

Ví dụ nếu dự án có API lấy danh sách sản phẩm:

  1. Mở Postman.
  2. Chọn phương thức GET.
  3. Nhập URL API Render.
  4. Nhấn Send.
  5. Kiểm tra HTTP status và response body.

Các mã trạng thái thường gặp:

Status Ý nghĩa
200 OKYêu cầu thành công
400 Bad RequestRequest không hợp lệ
401 UnauthorizedChưa xác thực hoặc thông tin xác thực không hợp lệ
403 ForbiddenKhông có quyền truy cập
404 Not FoundKhông tìm thấy đường dẫn hoặc tài nguyên
500 Internal Server ErrorCó lỗi xử lý phía server

20. Kiểm tra dữ liệu trên Aiven

Sau khi API tạo hoặc cập nhật dữ liệu trả về thành công:

  1. Mở MySQL Workbench.
  2. Kết nối đến MySQL Aiven.
  3. Chọn database quanlybanhang.
  4. Kiểm tra bảng tương ứng.
  5. Xác nhận dữ liệu đã được lưu.

Nếu API trả về thành công nhưng không thấy dữ liệu, hãy kiểm tra ứng dụng có đang kết nối đúng database và đúng schema hay không.

22. Quy trình debug theo thứ tự

Khi deploy thất bại, không nên sửa tất cả cấu hình cùng lúc. Hãy làm theo thứ tự:

  1. Kiểm tra build: Docker image có được build thành công không?
  2. Kiểm tra Java: phiên bản Java trong image có tương thích với ứng dụng không?
  3. Kiểm tra khởi động: Spring Boot có đọc đúng Profile và lắng nghe đúng port không?
  4. Kiểm tra biến môi trường: DB_URL, DB_USERNAME, DB_PASSWORD có được khai báo đầy đủ không?
  5. Kiểm tra database: Aiven có hoạt động, host/port đúng và kết nối được qua SSL không?
  6. Kiểm tra schema: database có đúng bảng và cột mà ứng dụng yêu cầu không?
  7. Kiểm tra API: endpoint có hoạt động khi gọi từ Postman không?

Lưu ý: Không chia sẻ công khai log chứa mật khẩu, token hoặc thông tin nhạy cảm khi nhờ hỗ trợ.

PHẦN VII. CHI PHÍ VÀ VẬN HÀNH

23. Những khoản cần quan tâm

Thành phần Nội dung cần kiểm tra
GitHubGói lưu trữ repository

AivenGói MySQL, giới hạn tài nguyên và điều kiện miễn phí

Không nên mặc định Aiven hoặc Render luôn có gói miễn phí. Các gói, giới hạn và điều kiện có thể thay đổi. Trước khi đưa ứng dụng vào sử dụng thực tế, cần kiểm tra chi phí hiện hành và thiết lập phương án sao lưu database.

Với dịch vụ Render miễn phí nếu được cung cấp cho tài khoản của bạn, ứng dụng có thể tạm ngừng sau một khoảng thời gian không hoạt động và cần thời gian khởi động lại khi có request. Điều này không đồng nghĩa database Aiven cũng ngừng hoạt động theo cùng cách.

Không nên xem việc ping dịch vụ liên tục là giải pháp đảm bảo uptime hoặc vượt qua các giới hạn của gói miễn phí.

PHẦN IX. BÀI TẬP THỰC HÀNH

Bài tập 1. Triển khai API sản phẩm

Sử dụng dự án Spring Boot quản lý sản phẩm có các chức năng:

  • Thêm sản phẩm.
  • Xem danh sách sản phẩm.
  • Xem chi tiết sản phẩm.
  • Cập nhật sản phẩm.
  • Xóa sản phẩm.

Yêu cầu:

  1. Tạo database MySQL trên Aiven.
  2. Đưa cấu trúc bảng và dữ liệu mẫu lên Aiven.
  3. Cấu hình Spring Boot theo Profile prod.
  4. Đóng gói ứng dụng bằng Docker.
  5. Deploy lên Render.
  6. Dùng Postman kiểm tra toàn bộ API CRUD.
  7. Xác minh dữ liệu thay đổi trên MySQL Aiven.

Bài tập 2. Thực hành xử lý lỗi

Lần lượt mô phỏng các tình huống trong môi trường kiểm thử:

  • Đặt sai tên biến DB_URL.
  • Sử dụng sai port database.
  • Nhập sai tên database.
  • Chạy ứng dụng bằng Profile local trên Render.
  • Sử dụng Docker image không tương thích với phiên bản Java.

Với mỗi tình huống, hãy ghi lại:

  1. Triệu chứng.
  2. Dòng log quan trọng.
  3. Nguyên nhân.
  4. Cách sửa.
  5. Kết quả sau khi sửa.

Bài tập 3. Câu hỏi củng cố

  1. Deploy là gì? Khác gì với chạy Spring Boot trên máy cá nhân?
  2. Vì sao không thể dùng localhost:3306 để kết nối MySQL trên Aiven?
  3. Dockerfile có nhiệm vụ gì?
  4. Vì sao nên sử dụng biến môi trường cho mật khẩu database?
  5. SPRING_PROFILES_ACTIVE=prod có tác dụng gì?
  6. DB_URL gồm những thành phần nào?
  7. EXPOSE 8080 có tự động đổi port mà Spring Boot lắng nghe không?
  8. Tại sao build JAR thành công nhưng ứng dụng vẫn có thể deploy thất bại?
  9. Phân biệt lỗi kết nối database với lỗi schema.
  10. Vì sao cần kiểm tra dữ liệu trên Aiven sau khi gọi API thành công?

Kết luận

Quy trình triển khai hoàn chỉnh của bài học là:

Spring Boot → Build JAR → Docker image → GitHub → Render Web Service → MySQL Aiven → Kiểm thử API

Trong đó, ba nội dung quan trọng nhất cần nắm vững là cấu hình Profile theo môi trường, quản lý thông tin kết nối bằng biến môi trường và đọc log để xử lý lỗi. Khi hiểu rõ ba nội dung này, bạn có thể áp dụng quy trình tương tự cho các dự án Spring Boot thực tế khác.

Ghi nhớ trọng tâm
  • Deploy là đưa ứng dụng từ máy cá nhân lên máy chủ/nền tảng để người dùng truy cập qua Internet.
  • Kiến trúc bài học: Client → Render (Docker + Spring Boot) → Aiven MySQL.
  • Phân biệt Local (localhost:8080, MySQL local) với Production (URL Render, MySQL Aiven).
  • Đóng gói JAR bằng mvnw clean package -DskipTests, sau đó đưa vào Docker image với Dockerfile.
  • Dùng Profile local và prod để tách cấu hình; kích hoạt bằng SPRING_PROFILES_ACTIVE=prod.
  • Dùng Environment Variables DB_URL, DB_USERNAME, DB_PASSWORD để bảo vệ thông tin kết nối.
  • Aiven cấp host, port riêng (không phải 3306) và yêu cầu SSL.
  • Kiểm thử bằng Postman và xác minh dữ liệu trên Aiven, không chỉ dựa vào response API.
  • Khi lỗi, debug theo thứ tự: build → Java → khởi động → biến môi trường → database → schema → API.
  • Không commit mật khẩu lên GitHub; không mặc định có gói miễn phí; cần kiểm tra chi phí và backup.
